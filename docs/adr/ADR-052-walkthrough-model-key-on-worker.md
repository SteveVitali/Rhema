# ADR-052: The worker accesses the provider key secret for walkthrough generation (named exception)

- **Status:** Accepted
- **Date:** 2026-10-03
- **Ticket:** RUN.1
- **Requirement ids:** REQ-IDE-19, REQ-ARCH-30
- **Spec:** §5.5 (walkthrough), §13.2 (stages/secrets)

## Context

Every delivered run's `run.walkthrough` job failed with `walkthrough unconfigured`: the worker's
generator was bound to a stub because the Pulumi program never named a model-key env for it. The
walkthrough is a §5.5 "what the run did" summary generated by a model call — it needs a provider
key, but REQ-ARCH-30 confines provider keys to `egress-proxy` ("never reachable from the model's
process" governs *agent* traffic, and no secret may be a plaintext env var to `web`/`collab`).

The worker already had one named exception: `INGEST_MODEL_KEY_SECRET` for ingestion
reconstruction (a server-side bookkeeping call that never enters an agent's tool surface). The
walkthrough generator is the same shape — a worker-side model call whose prompt is the run's own
delivered facts, not user prompt material.

## Decision

- **`WALKTHROUGH_MODEL_KEY_SECRET` is wired on the worker** in `infra/pulumi/compute.ts` (inside
  the `isWorker` envs block) pointing at `secretVersion(secrets.anthropicApiKey)` — the secret
  *name's* `/versions/latest`, never the value (REQ-ARCH-30 preserved: no plaintext env).
- **The worker's `loadWalkthroughGenerator`** (`apps/worker/src/walkthrough-generator.ts`)
  resolves the named secret through the `access` seam at boot: a valid non-placeholder key binds
  `AnthropicWalkthroughGenerator` (model `claude-haiku-4-5`, max 400 output tokens, ≤200-word
  brief); a missing/placeholder key binds a failing stub that reports `walkthrough unconfigured`
  — the failure is *exposed for retry* on the run card, never silently empty.
- **The IAM comment names the exception pair** (`infra/pulumi/iam.ts`): `anthropic-api-key` is
  primarily owned by `egress-proxy`; the worker's access is an explicit, documented exception for
  `ingest.reconstruct` + `run.walkthrough` only — never `web`/`collab`/`run-task`.
- **A deploy-config test pins it** (`infra/pulumi/compute.test.ts`): the env must be inside the
  worker container block and reference the secret version, so a future refactor cannot quietly
  unbind the live generator back to the stub.

## Consequences

- `run.walkthrough` jobs on stages with `anthropic-api-key` produce real walkthroughs; stages
  without the secret keep the honest `walkthrough unconfigured` error the card's Retry can act
  on.
- The worker's secret-access surface is now two named exceptions on one key; both are commented
  in code + this ADR, and neither reaches `web`, `collab`, or the agent sandbox.
- Regenerating a walkthrough on a failed run (e.g. `01M3SK62YZST272B35CG12K6TW`) works through
  the same self-healing re-enqueue — the failure state is a retriable job, not a dead end.

## Alternatives considered

- **Route the walkthrough call through `egress-proxy`.** Rejected — the proxy brokers *agent*
  egress inside runs; a worker bookkeeping call behind it would acquire the agent policy surface
  (domain allowlists, audit labels) it doesn't need, and the worker already holds a sanctioned
  key exception for the identical ingestion-reconstruction use.
- **A second dedicated secret (`walkthrough-api-key`).** Rejected — duplicates the same provider
  key under two names; the exception is the *worker reading a provider key*, not which name it
  carries. One secret + one documented exception pair is the smaller blast radius.
- **Generate walkthroughs without a model (template fill).** Rejected — §5.5's walkthrough is
  prose summarising what the run did; a template cannot produce it truthfully.

## Revisit trigger

Reopen if provider-key governance is restructured (e.g. a dedicated worker-key secret per
service, or egress-proxy grows a bookkeeping lane), or if the walkthrough model moves off the
same provider as ingestion.

## Addendum 2026-11-05 (R7DEP.1 / D-R7COPY.0-2)

The walkthrough generator was retired by R7COPY.0 under ADR-130 (the generated walkthrough was a
lazy post-delivery call outside the Review output). The `WALKTHROUGH_MODEL_KEY_SECRET` env binding
on the worker template was therefore dead config; R7DEP.1's deploy plan removes it from
`infra/pulumi/compute.ts`. This decision's worker-side exception **narrows to
`ingest.reconstruct` alone** — the `worker-reads-anthropic` grant stays (reconstruction still
spends through it), and `apps/worker/src/env.ts` keeps the old name as a read-side legacy
fallback so a stage provisioned only with the old name cannot lose resolution.
