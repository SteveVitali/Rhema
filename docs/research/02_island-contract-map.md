### F2 — Island activation is SSR-emitted `<script defer>` + attribute/json markers, enforced by tests

All islands are `defer`, CSP-nonced, and fail inert (a missing artifact 404s with an empty body and the page still works).
**Status:** VERIFIED

### F4 — The collab session protocol (client `collab.ts` ↔ `apps/collab` Hocuspocus extension)

**Claim:** Document name `draft:<draftId>`; the `__Host-` session cookie rides the WS upgrade (LB path-routes `/collab`; CSP `connect-src` carries the configured origin explicitly for WebKit). Server `onAuthenticate` resolves session → workspace-scoped binding under RLS: held run lock → `connectionConfig.readOnly`; showcase → readOnly; frozen head + write intent + existing human working head → `AuthRefusal` whose `reason` is JSON `{code:"frozen_fork",draftId,draftN}` (client `onAuthenticationFailed` parses it → `onFork` → `rebind`); frozen + non-human working head → readOnly; frozen + no working head → writable (lazy fork at first store); non-human-origin working head → readOnly. `connected` pushes `rhema.readonly` stateless so the pill never lies. `onLoadDocument` returns `live_docs.y_state` or seeds `markdownToUpdate(canonical markdown)`. `onStoreDocument` (debounce 2 s, max 10 s) writes `y_state`+`state_vector`, then — lock → `pre_run` checkpoint + broadcast `rhema.readonly` + `closeConnections`; else `saveManualRevision` → canonical markdown → artifact version, and on head move broadcasts `rhema.fork` + closes. Client→server stateless: `rhema.provenance` (stashed for next materialization), `rhema.restore{cause:named|blur}` (⌘S/pagehide). Server→client: `rhema.fork`, `rhema.readonly`, `rhema.restore_point{restorePointId}`. Rebind keeps ONE Y.Doc but builds a FRESH provider and re-homes/clears the IDB store. Restore cadence: 5-min activity deltas, 24-h snapshots, named always snapshot; hourly retention sweep.
**Status:** VERIFIED
**Evidence:** client `apps/web/src/client/collab.ts:17-225` (fragment name :18; wsUrl + `?intent=ro` :94-98; provider hooks :103-165; sendProvenance/markRestorePoint/flushOnHide/rebind :185-218); server `apps/collab/src/auth.ts:134-250` (refusal cases :150-247); `apps/collab/src/extension.ts:138-264` (hooks; fork/readonly broadcast :211-230; stateless :239-263); `apps/collab/src/materialize.ts:108-266` (store + markRestorePoint); `apps/collab/src/server.ts:73-82` (debounce 2s/10s, `unloadImmediately:false`); cadence constants `packages/mirror/src/restore.ts:56-58`.
**Retrieved:** 2026-10-07T20:36:13Z
**Implication for the spec:** The port must speak this exact stateless vocabulary (or version it) and preserve: cookie-only auth, `draft:<id>` naming, rebind-not-rename semantics, the frozen-fork UX (banner "Editing vN · findings from vM follow your text"), and read-only attach paths. **Outline delta:** EXTENDS — the auth-refusal JSON channel and the out-of-band `rhema.fork` broadcast (needed because `closeConnections` leaves the socket half-open, N8 walk) are load-bearing.

### F8 — `landing.ts` is a three-job pre-auth island: IndexedDB drop-zone hold, `/app/new` claim hydration, server-confirmed consumption

**Claim:** (1) On `[data-dropzone]` (landing hero): file pick/drop/paste of .md/.markdown/.docx/.pdf/.txt ≤10 MB → `putHold` into IDB `rhema-hold`/`holds`/`landing-dropzone` → beacon `landing.dropzone_used` {kind,size,token} (never bytes, never filename) → `/signup?intent=review&held=1`. (2) On `form[action="/app/new"][data-held]` (EVERY /app/new load): reads the hold, hydrates `input[name=file]` via `DataTransfer`, stamps `input[name=heldToken]` only when attached, defaults title to filename stem, writes `[data-held-notice]` + a Discard button (the other deletion path). (3) On `[data-held-consumed]`: deletes the hold ONLY when the server-echoed `?hc=` token matches the record. Beacon transport: `sendBeacon` → `fetch keepalive` fallback, POST `/a/landing`.

### F10 — All island↔server traffic is same-origin and credential-free in the bundle; form POSTs are the write path for everything except the two autosaves

**Claim:** No bundle holds a token: HTTP calls use `credentials:"same-origin"`/`sendBeacon`; the WS upgrade carries the session cookie; the web routes forward the session to the api. The islands' only writes are: editor.js `/save` POST + pagehide beacon; outline.js form-POST autosave; landing.js `/a/landing` beacon; ide.js theme/paper POSTs + palette-search GET + SSE GET. Every other write (note, cancel-run, revise, dispositions, gate answers, chat, steering) is an SSR `<form method="post">` that works without JS — ide.js's finding verbs literally `.click()` the SSR'd buttons (`[data-apply]`, `[data-verb=<v>]`).
**Status:** VERIFIED
**Evidence:** credential comments + same-origin fetches `page.ts:295`, `editor.ts:91-95,161`, `ide.ts:311-316,541`; form-click verbs `ide.ts:641-659`; form actions in SSR `page-editor.tsx:353,368,467-473`, `source-editor.tsx:159,302,351`, `pages.tsx:1123`; REQ-ARCH-33 headers in every island file's leading comment.
**Retrieved:** 2026-10-07T20:36:13Z
**Implication for the spec:** The "server contract" is mostly HTML: form actions, `data-*` templates, `ed.*` field grammar, embedded JSON. A React port that collapses SSR forms into client-side mutations must keep the same endpoints + payload grammars (or the no-JS story dies with the forms).
**Outline delta:** CONFIRMS progressive-enhancement architecture; EXTENDS with the complete endpoint table below.

## Open questions

1. **editor.js disposition** — `GET /edit/:draftId` redirects; `SourceEditor`/`editorElement` are unrouted but built, served, and tested. Is Source mode in scope for the SPA port (a route to restore) or dead code to delete? Its `/edit/:draftId/*` endpoints must survive either way (page.js's poll).
2. **`intent=ro`** — `CollabSessionOptions.intent` is implemented (collab.ts:40,96) but no caller passes it; the `/v/:n` read path currently attaches write-intent and relies on server verdicts. Intended for a future frozen-read wire, or removable?
3. **`data-save-url` on `data-page-root`** — emitted (page-editor.tsx:319) but never read by page.ts (no `saveUrl` reference). Vestige to prune, or a contract a React port should consume for an HTTP-save fallback when `collabWsUrl` is absent?
4. **⌘S dual binding** — page.ts handles it directly (stateless `rhema.restore`); ide.ts dispatches `rhema:restore-point` CustomEvent with no current consumer. One owner in the SPA?
5. **Polling scope** — the 10 s lock poll is per-editor; an SPA could hold one doc-level subscription. Does the spec want the poll semantics (visible-only, 10 s, rebase-on-draftId) preserved verbatim or subsumed by a push channel?
6. **Multi-tab collab** — two tabs on the same draft each open a provider + IDB store; nothing in the island coordinates them (y-indexeddb syncs via IDB broadcasts implicitly). Verified behavior or known gap for the spec to name?
7. **`rhema:finding-action` event** — dispatched `bubbles:true` on finding cards (ide.ts:645); no in-repo listener found — is a consumer planned (chat/anchored composer), or is it spec surface to keep?

## Spec requirements emitted

- **REQ-ISL-1** — The SPA must bootstrap each former-island zone from server-serialized state equivalent to today's contract: PM doc JSON, provenance map, findings (with verbatim `anchor` blobs for decoration re-resolution), PaletteData, feed label maps + `lastSeq`, theme/pane endpoints, all label `data-*` templates (copy stays server-owned, REQ-ARCH-33).
- **REQ-ISL-2** — Page editing must preserve the four-layer autosave (bound Y.Doc → IndexedDB offline survival → collab WS → debounced server materialization) or a transport of equal durability: offline queue, no beforeunload dialog, pagehide/`hidden` flush.
- **REQ-ISL-3** — ⌘S is the only manual save verb (named restore point); there is no Save button and no unsaved-changes dialog anywhere.
- **REQ-ISL-4** — The collab wire protocol is contractual: doc name `draft:<id>`, cookie-auth upgrade, stateless `rhema.provenance`/`rhema.restore{cause,label}` outbound and `rhema.fork`/`rhema.readonly`/`rhema.restore_point` inbound, `frozen_fork` auth-refusal JSON, and rebind-keeps-the-Y.Doc semantics.
- **REQ-ISL-5** — The §6.3 lock contract: 10 s visible-only doc poll returning `{draftId, lock, findings, venueCap}`, rebase on `draftId`, editable/readOnly flip + banner + pill, and rail `data-lost` resync — or a documented push equivalent.
- **REQ-ISL-6** — The single sync pill renders §5.10's verbatim vocabulary (`synced`/`syncing`/`offline · n changes queued`/`read-only`), aria-live, one indicator per page.
- **REQ-ISL-7** — Provenance capture must stamp `human`/`pasted`/agent origins (`ORIGIN_META`), keep agent transactions out of the human undo stack (`acceptProposalTr`, yUndoPlugin scoping), and flush captures on the stateless/600 ms channel.
- **REQ-ISL-8** — The §5.12 keymap must keep focus-zone scoping (findings chords inert while caret is in the Page or a field); `dispatchIdeKey` is pure and ports verbatim.
- **REQ-ISL-9** — The palette/command surfaces never POST: every activation is a navigation or sheet GET; the sheet owns run creation.
- **REQ-ISL-10** — Pane/theme/font/reader state persists to the documented localStorage keys, per user × project, never the URL (`?focus=1` applied then stripped is the sole exception).
- **REQ-ISL-11** — Every zone keeps a no-JS floor: PmPreview read view + working note/cancel/revise/disposition/outline/dropzone forms; a missing JS artifact must degrade, not fail.
- **REQ-ISL-12** — No bundle may hold a credential; all island traffic stays same-origin (cookie auth incl. the WS upgrade); no protocol/eval text in shipped JS (REQ-ARCH-33 marker checks cover `public/*.js`).
- **REQ-ISL-13** — The landing hold keeps: client-side IndexedDB storage ≤10 MB with the extension allowlist, beacon carrying token+kind only (never bytes/filename), hold durable across /app/new visits, deletion only on token-matched `?hc=` consumption or explicit Discard.
- **REQ-ISL-14** — The live feed keeps: same-origin SSE proxy, `?after=<seq>` + `Last-Event-ID` resume, named-event dispatch keyed by the server-supplied label maps (fail-closed rendering), 400-row DOM bound, and run-card meter/phase patching.
- **REQ-ISL-15** — A pre-paint theme-resolution equivalent to `themeBootScript` must ship (SSR attr → localStorage → default, `auto` subscribes matchMedia) — no wrong-theme flash.
- **REQ-ISL-16** — The `/edit/:draftId/doc|save|note|cancel-run|revise` transport routes are consumed by the Page island and must not be removed even if the CodeMirror surface stays unrouted; a port decision on Source mode is required (Open question 1).
