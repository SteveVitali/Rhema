## Goal

BL-99 part 1: plumb token-delta events from the agent harness to the SSE boundary so a
client can render chat tokens as they arrive. Today a `chat_turn` renders only at turn
completion (the U6.chat leg asserts the rendered bubble). Add a `chat.token` (or
equivalently-named) event carrying `{turnId, seq, text}` deltas: the run-task's §12.5 event
stream already carries per-batch events to the harness — extend that pipe (or the
run-task's own event emission) so token deltas reach `postEvents`/`eventWriter` with the
same ordering guarantees as every other event (seq-monotonic per run), flow through Redis
fanout, and arrive on `/events` SSE.

## Spec §§ / anchors

- `apps/run-task/src/agent-entry.ts` (the harness event fd — no token crosses it),
  `event-transport.ts`, `event-buffer.ts`; `packages/orchestrator` event schema + writer
  (`internal-api.ts` append paths, `publishCommittedEventHighWater`); the api's SSE
  `/events` route; `packages/contracts` event vocabulary.
- Ordering + visibility rules: a token event must never outrun its turn's start event on
  the wire; late subscribers must not replay stale tokens (tokens are ephemeral — decide
  and document whether they persist to `run_events` or are fanout-only; the ADR answers
  this explicitly).
- **Privacy boundary (REQ-SPEC/ADR-125):** no private protocol or eval text in payloads;
  token text is model output for an authorized turn only.
- The commit-time wakeup machinery (322_R6FIX.51) already exists — token events ride it;
  do not add a second wake path.

## Acceptance (deterministic)

- Unit + integration: a stubbed turn emitting N token deltas produces N ordered
  `chat.token` events on the run's event stream with monotonic seq, visible on an SSE
  subscription before turn completion; existing `U6.chat` and notification legs unchanged;
  concurrent subscribers each see all deltas.
- `pnpm turbo build lint typecheck` + orchestrator/run-task/api suites + `check:no-cookies`/`protocol-markers` green.
- Preview walk: a test-tenant chat turn on the preview emits token events (assert via the
  probe/console read — render lands in UX.9).

## Out of scope

- Client rendering (UX.9), backpressure/drop policy beyond the ADR's decision, any change
  to `chat_turn` completion semantics, metering.
