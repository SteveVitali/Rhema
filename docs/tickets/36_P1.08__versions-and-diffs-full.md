freshness notes — so every artifact is reachable without ever showing a filesystem.

## In scope — Stage A (code + tests, PR-able)

1. **The version rail (REQ-IDE-32's rail half — the fork rule landed at PRB.07).** Chips across
   the top of the Page and the Browser's Drafts section: `Outline → v1 🔒 → v2 🔒 → v3 ● draft`
   with per-chip origin (`drafted_from_outline | response_to_review | human_upload |
   human_revision | duplicate | imported | cut`), reviewed/answered flags, word count, date;
   🔒 = frozen. Human-revised versions carry the **"claims pending verification"** chip
   (ledger N4; REQ-PROD-11 — the `drafts.claims_pending_verification` column exists; render it
   and link to the next Review's scope card). Each chip carries the **open-obligations chip** —
   `⚑ 3 open · 2 addressed`, blocking/major only, full list one click away (REQ-OBJ-6's rail
   half; the what-changed strip half lands in item 3). `[`/`]` step versions; `⌘⇧C` opens
   compare-with-previous (P1.06's dispatcher routes the chords).
2. **Restore-points dropdown (REQ-IDE-34's UI half — storage is P1.03).** Grouped "Earlier
   today / Yesterday / Before Review of vN / Named"; picking one previews the diff against the
   current head; *Restore* applies it as an **undoable** transaction (a transaction or a new
   head per the P1.03 mechanics — pick what the transport supports and record it). Restore
   never touches correspondence or agent memory — assert it. Per §5.1's disclosure rules,
   restore points older than today render under the dropdown's Advanced disclosure; named
   points are always listed.
3. **Compare — three layouts (REQ-IDE-33 amended, server-side read-only).** At
   `/p/:project/v/:n/diff/:m` for any two versions: **Side-by-side** (the third layout joining
   PRB.06's pair), **Inline**, and **What changed and why** — the existing service extended to
   arbitrary version pairs (it already handles the review-pair case via `/revisions/:cid`;
   generalize to `(draftN, draftM)` including human-revision diffs where no response ledger
   exists — hunks then group entirely under *Unlinked* with the "coherence read" caption). Move
   cards carry the discharge line naming the obligation ("discharges OBL-3 (F-07, carried from
   v2) — verified by gap check") and the header strip summarizes "7 obligations addressed · 1
   rebutted · 2 still open" beside the move counts (REQ-OBJ-6's compare half). Rebutted
   findings appear with rationale and no hunk. **Inline comments on any hunk become
   `Guidance{source:'inline_comment'}`** for the next Revise run — retarget the PRB.06 hunk-
   comment route accordingly (check what it writes today; the destination is a Guidance row,
   not a note string).
4. **The artifact Browser — the Files pane (REQ-IDE-35/36/37; REQ-VIS-3 amended).** Typed
   sections, never a filesystem tree: **Outline** (versioned if edited after v1) · **Drafts**
   (the rail's entries + working head + companion docs) · **Rounds** (per round: drafting note,
   claim ledger, discourse report, second read, Editor's letter, response letter, run reports,
   walkthrough — the piece brief is I, surfaced only at the Confirm-scope card) · **Research**
   (Drafter source library as a list — note bodies on click; Assistant chat sources + Research
   notes; the Editor's fetched URLs only — never note bodies) · **Voice** (linked voice summary
   card + staleness pill + charter read-only with "Add guidance") · **Assets** (figures,
   uploads, CSL-JSON bibliography) · **Advanced** (disclosure — the I kinds: drafting dossiers
   per version; cut lists / vulnerability maps arrive with their 1.x workflows — section may
   render absent until content exists, but the disclosure mechanics must be in place).
   **Hidden entirely, never listed:** Editor working notes and research note bodies, hold-out
   identity pre-calibration, corpus notes, consolidation notes, run transcripts.
5. **Row contract (REQ-IDE-36/37; ledger D21).** Every artifact row and Page header carries: a
   **provenance badge** (`Drafter · Draft run 12 · Writing` / `Editor · Review run 14 · Letter`
   / `You` / `You (edited from Drafter v2)` / `Imported (.docx)` / `Corrected`) linking to the
   producing run + phase; a **lock-state icon** (✎ editable · 🔒 immutable · 👁 inspect-only ·
   ⛔ sealed — count only); a **freshness note** when a describing artifact is stale relative
   to its subject ("drafting note describes v1 as delivered; v1 has since been edited").
   Agent-memory artifacts open read-only; the voice charter offers "Add guidance" instead of
   editing. The section contents are driven by `artifactPolicy` levels — **I kinds appear only
   via links/"Show working" inside the Advanced section; H kinds have no route at all** — and
   the REQ-VIS-3 AC runs as a snapshot test: the default tree over the three seeded projects
   contains no I/H row.
6. **Freeze surfaces (REQ-DATA-21/24 UI halves).** The rail + cards expose freeze state and the
   "v4 · draft" head labelling; opening a frozen vN for editing offers the §5.4 fork path
   (PRB.07's semantics — the rail links into it rather than reimplementing).
7. **Deep links.** `/p/:project/v/:n`, `/v/working`, `/v/:n/diff/:m`, `/a/:artifactId`,
   `/f/:findingId` all resolve inside the IDE shell with the target focused and the rest of
   the layout from the user's last state (REQ-IDE-1's remaining half; `?focus=1` honoured).
8. `turbo build lint typecheck` + `pnpm test` green; vocabulary lint on chip/section strings
   (**Files** for the pane label, **Obligation** never "backlog").
