## Defect (BL-135)

HSTS stamped only when `x-forwarded-proto === "https"` or a raw `https://` URL — a deployed hop
missing the forwarded header got no stamp. The forwarded header is the fragile dependency; the
client-facing hop behind the LB is always TLS (container plaintext is internal).

## Change (apps/api/src/index.ts, apps/web/src/server.ts)

Deployed-image discriminator = the image-baked deploy SHA (`deps.buildGitSha ??
RHEMA_BUILD_GIT_SHA` — the JOURNEY.1 provenance value, only ever set on built images): on a
deployed image the stamp is unconditional; off-image (dev/tests, no SHA) the prior TLS-signal
gating stands — RFC 6797's SHOULD-NOT for HSTS over insecure transport still holds for direct
plaintext dev serving. Same policy value (`max-age=31536000; includeSubDomains`, no preload),
same middleware position.
