# 340_R6FIX.58 — vendored SDK resolvable from a non-worktree source (F-R7UX.9-1)

**Kind:** run-time insert · **Base:** `origin/main` (flat insert) · **mergePolicy:** OPERATOR

## Finding

- **F-R7UX.9-1 (LEDGER):** an `_ALLOW_PLACEHOLDER_SDK=1` run-task image cannot execute the agent —
  the vendored `@anthropic-ai/claude-agent-sdk` is gitignored operator-held state, so any Cloud
  Build submit from a clean worktree produces a no-engine image (`ERR_MODULE_NOT_FOUND` at
  `step.started`, observed on `pr-426` run `01M8BF6BJMSF2NC56ZG5E2ZYDS`). Preview walks exercising
  a real `chat_turn` needed a manual copy-from-operator-checkout workaround.

## Scope

- `infra/cloudbuild/image-set.yaml` — new `_SDK_BUNDLE_URI` substitution (default `""`) +
  `sdk-bundle-fetch` step (cloud-sdk image) running **before** `image-set`: when `_SERVICES`
  includes `run-task` and `_ALLOW_PLACEHOLDER_SDK != 1` and the URI is non-empty, it downloads
  the tarball and extracts `claude-agent-sdk/` + `claude-agent-sdk-linux-x64/` into
  `apps/run-task/vendor/` — the existing context assert then proves the trees landed.
- `infra/config/cloudbuild.test.ts` — pins fetch-step ordering, cloud-sdk image, gating, and the
  hydrate targets matching the Dockerfile's required files.
- `apps/run-task/vendor/README.md` — documents the bundle seam.
