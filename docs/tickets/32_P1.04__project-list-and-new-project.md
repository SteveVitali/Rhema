## In scope — Stage A (code + tests, PR-able)

1. **The attention-grouped list (REQ-IDE-3/4/6 amended).** Rows grouped **Needs you / Running /
   Ready to read / Quiet** (Quiet collapsed by default with its Unfiled/voice sub-counts);
   Needs-you rows sort by soonest deadline; Ready-to-read clears when the deliverable is
   opened. Each row: state icon (animated = running, amber = needs you, green = ready, grey =
   quiet, red = failed), title, current version, a ≤120-char status line, voice chip (or
   *Unfiled*) with its staleness pill, and **one** state-matched primary action — all derived
   from the state function + run/version tables, never a stored opinion. The status line is
   assembled from stored facts (state, phase, finding counts, verdict) deterministically;
   where a delivered run carries a walkthrough (P1.05) it may source that — record the choice
   and keep the ≤120-char contract either way.
2. **Voice grouping (R2; REQ-PERSONA-21 amended).** `Group by: Attention ▾ / Voice` one click
   away, remembered per user; under Voice, *Unfiled* is the first group and each group header
   carries the voice's pill plus an "N projects use an older profile" count (the
   workspace-level entry to Adopt refreshed profile — the Adopt flow itself is PRB.10's/P1.14's;
   wire the count + link). Voice and Protocol filter dropdowns, Sort (Recent default), and an
   Archived checkbox complete the bar.
3. **Row actions.** Open · Rename · Duplicate (copies drafts + outline + voice link, never
   correspondence; `origin=duplicate` — REQ-PROD-8's enum) · Change voice (the §9.6 policy
   surface — free until v1, fork/wrong-voice sheet after) · Export… (the PRB.11 dialog) ·
   Archive (soft; archived = read-only, runs blocked per §6.3) · Delete (soft, 30 days). Wire
   each to api routes; membership checks as usual.
4. **Search.** The `/app` search field matches titles, voice names, venues, and text inside
   drafts and letters via the server-side `tsvector` index on materialized markdown (§11.4 —
   if the migration lacks the index/column, add it forward-only). Results deep-link per §4.2.
   Full cross-project search is 1.x — note the boundary; the `⌘K` palette's *Go to* section is
   P1.06 and consumes the same endpoint.
5. **The new-project flow (REQ-IDE-5).** Exactly three entry cards — **Scratch** (chat +
   research), **An outline** (upload/paste .md .docx), **A draft** (upload/paste .md .docx .pdf
   .txt) — plus Title, Protocol, Venue, Voice. No fourth entry (the draft+review import is a
   1.x in-project action).
6. **Conversion preview before Create** on the upload entries — §5.3's make-or-break moment,
   now on the live PRB.20 path: source beside converted Rhema Markdown; the count line
   ("7,900 words · 41 footnotes · 23 citation-like spans · 2 tables · 1 figure" — reuse
   `@rhema/markdown`'s `renderCountLine`/`detectCounts`); the warnings list with anchors;
   **Create and fix later** (default — warnings become a *Conversion notes* card on the
   Timeline + `[unconverted]` markers) and **Fix now** (opens the affected block in the Page).
7. **Protocol/venue/voice defaults (REQ-GENRE-4; REQ-PERSONA-20).** Protocol cards for the four
   seeded protocols, each with tagline, "what the Editor will hold you to", and a typical cost
   band; default = Essay for Unfiled, Academic when the linked voice's structure repertoire
   records `apparatus: full`, otherwise ask once. Venue is a typeahead over the protocol's
   venue table with free text allowed; target length prefills from the venue. Voice defaults to
   *No voice* (⚑), the picker lists Your voices and House styles with pills, allows
   `never-built` voices with a hint, offers *Create a voice…* inline. Version labels are
   importable (REQ-PROD-8): the draft entry accepts a declared starting `vN`; rounds number
   independently of versions.
8. **Landing per entry.** Create lands the user on the project with the correct next-step card
   at the Timeline head: *Draft* → `v1 (imported)` on the Page + "Review v1" card with estimate;
   *Outline* → outline on the Page + "Draft v1" card with estimate; *Scratch* → the
   empty-project state with the Chat entry's next-step card (the Desk-open-on-Chat landing with
   its four chips needs the Assistant surface — **P1.11**; land the next-step card now and note
   the Desk half as P1.11's).
9. **Secondary chips + full reachability (REQ-PROD-9 full surface; REQ-PROD-10).** Up to two
   secondary chips on the project surface from the protocol's `workflow_availability='default'`
   ∩ state; Suggested next is never the only affordance — a workflow menu lists every workflow
   with disabled-reason tooltips until the ⌘K palette (P1.06) takes it over. Keep the menu a
   thin surface over the same registry the palette will read.
10. `turbo build lint typecheck` + `pnpm test` green; vocabulary lint on new strings
    (**Unfiled**, voice not persona in UI copy).
