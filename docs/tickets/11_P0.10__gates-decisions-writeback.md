## Goal
Approvals as durable mechanics (no UI yet): the twelve gate kinds with their per-kind deadlines and
`onExpiry` behavior, `Decision` rows for every resolution path, `Guidance` records, and the
REQ-SPEC-9 overlay flow that serializes structured gate edits into the files the next phase reads.

## Load
- Spec §6.4 end-to-end (the R3 deadline table verbatim; mechanics items 1–8; REQ-GATE-1…10;
  REQ-SPEC-1's one rule set; REQ-DATA-35/36 amended; REQ-RUN-5/6), §6.5 (Guidance object; steering

## In scope — deliverables
1. **Gate rows + kinds:** the twelve-kind enum with `blocking`, `onExpiry`, `held`,
   `pausedWhileReading`, `presenceDeadlineAt`, `resolvedAt`; per-kind defaults exactly the §6.4
   table (Approve plan 24 h `proceed_conservative`; Confirm scope informational/blocking cases;
   Approve triage waits; outline/thesis wait; sample 24 h within cap; cut list 2 h; spend + refusal
   kinds wait and never auto-proceed).
2. **REQ-SPEC-1 override rules:** `Project.approvalOverrides` validation (lengthen/remove/add ≥2 h
   for wait-default kinds; never shorten; never on spend/refusal kinds — schema-rejected); exactly
   four non-human resolution mechanisms, each writing `Decision{by}` (`timeout`, `policy` ×2 paths,
   `trial`), presence path recorded `by:'timeout', presence:true`.
3. **Expiry machinery:** `gate:<id>` scheduled jobs — P0.08 only *registers* the job type; this
   ticket **owns scheduling and handler semantics**; conditional updates
   (`WHERE resolved_at IS NULL`, act-only-if-changed); expiry job re-reads `deadline_at` and
   reschedules if moved; pause-while-reading and bounded activity extensions (+10 min, cap +24 h)
   as server-side deadline state (REQ-RUN-6 amended; review 13 F9). Reminder notifications emitted
   as events (email transport lands in PRB.9).
4. **Resolution API:** `POST /runs/:id/gates/:gid {decision}` — decision row, expiry-job cancel,
   overlay serialization (P0.04 serializers) into a new `artifact_version{createdBy:{kind:'user'}}`,
   `Decision.overlayVersionIds`, state → `queued`, `run.resume{from_step}`; policy-skipped gates
   still write `Decision{by:'policy'}` rows (REQ-DATA-36); "Approve and run autonomously" turns off
   later named gates for the run.
5. **Guidance (REQ-GATE-9/10/11):** the §6.5 `Guidance` object; standing guidance (project scope,
   retirable, never deleted); gate-text and gate-edit sources; `consumedBy` population at phase
   start; never delivered into independence contexts (with P0.09's mounts); rendered into the
   skill's `guidance` input as a dated, sourced list.
6. **Re-plan interaction:** plan-artifact hash change after approval re-opens Approve plan (or
   auto-approves within the consented cap under Run-to-completion) — consuming P0.08's back-edge
   signal (§6.5; REQ-GATE-6).

      mechanism (REQ-SPEC-1). *(deterministic)*
- [ ] Spend kinds (`confirm_cost`, `spend_overrun`, `resume_partial`) never auto-proceed under any
      policy/override/timer combination (property test). *(deterministic)*

      is schema-rejected; adding 2 h to `approve_triage` works. *(deterministic)*
- [ ] Overlay round-trip (Phase-0 exit criterion): an Approve-plan/triage edit serialized to the
      file, resumed run's mirror carries the overlay, and the skill sees the user's rows with
      `actor: user` (REQ-SPEC-9; REQ-WF-9's enforcement path). *(deterministic with FakeEngine;
      re-verified live in P0.15)*

      (race fixture). *(deterministic)*
- [ ] A queued note becomes `Guidance{source:'queued_message'}` delivered at the next phase
      boundary and never into a judge/independence context (fixture with P0.09 manifest).
      *(deterministic)*
