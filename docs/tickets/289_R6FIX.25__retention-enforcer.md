prefixes no write path used (dead rules); `admin_actions` (the `audit` class, declared 90 days)
had no prune job; SECURITY.md's retention claim overstated enforcement.

## Change — per the 2026-11-16 operator ruling (drop dead rules; prune at 90d as declared)

  dropped from the app buckets (the access-logs bucket's real unscoped 90-day rule stays). No
  rebind — no class-prefixed write path exists; expiry is honestly DB-owned.
- **`admin_actions.retention` worker job** (new queue, daily `35 3 * * *`, registered in
  WORKER_QUEUES + createQueue + boss.work/schedule): `handleAdminActionsRetention` deletes
  `admin_actions` rows older than `RETENTION_SCHEDULE.audit.days` — the `audit` class's declared
  enforcer. SYSTEM-scoped like `run_events.retention` (the table is not under RLS).
- **infra/config/retention.ts:** the honest class → store → enforcer binding table recorded in
  the file header.
- **SECURITY.md:** the retention paragraph now names each class's actual enforcer and warns that
  a new class needs its enforcer bound, not just a schedule row.
- **retention-backup.test.ts:** asserts the dead `matchesPrefixes` generation is gone, the real
  access-logs rule stays, and `admin_actions.retention` has a live `boss.work` binding (the
