## Defect 1 — U4.controls: `reason_code` radios render OS-default (product)

The nightly `U4.controls` probe flagged 38 native-styled `<input type="radio" name="reason_code">`
on `/app/inbox` (`appearance=auto`, `bg=rgba(0,0,0,0)`). These are the `ReasonRadio` chips in
`packages/ui/src/dispositions.tsx` — a **named RV-36 exemption** whose own reason text claims
"the KIT-1-styled native radio stays". The claim was never true: the input carries no styling at
all. The defect only became visible when the journey tenant's inbox first rendered disposition
rows (jrn-a's funded-window work 2026-11-23 placed gate/decision rows in its inbox — the previous
five green nightlies simply had none to render).

Fix: the radio now carries `className="ui-d-radio"` + inline `accent-color: var(--accent)`
(same inline-style convention as the sibling `chipLabel`) — the true "KIT-1-styled native" the
exemption names. The `ui-` carrier class also satisfies the probe's primitive-carrier rule
honestly: the control is now kit-styled, not exempted-from-styling. No `uiCss()` bytes — the
24 kB REQ-KIT-5 bound is at ceiling (24640 > 24576 with the rule inline — rejected).
