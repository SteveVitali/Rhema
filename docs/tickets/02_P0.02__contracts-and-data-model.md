## Goal
The one shared decision the whole build hangs on: `packages/contracts` (zod schemas for every
payload, enum, event, and sidecar) and `packages/db` (the §11 schema as forward-only migrations, the
RLS wrapper, the seed from the three real projects). Every later ticket consumes these; none may
re-declare them.

## Load
- Spec §11.1–11.4 end-to-end (principles, entity overview, domain types, storage strategy + DDL and
  its in-Postgres invariants), §11.7 (obligation + claim-source DDL), §8.1–8.2 (visibility policy
  table; the 63-kind closed enum), §4.3 + Appendix D.2 (canonical vocabularies / reserved strings),
  §12.5 (event catalogue payloads), REQ-IDE-50 renames.
- **Adopted by reference (spec §0.1) — open and apply renames:** design/3 §3.2 (full domain-type

## In scope — deliverables
1. **`packages/contracts`:** the §11.3 domain types as zod schemas — including `ArtifactKind` (the
   closed 63-value enum, REQ-SPEC-14), `WorkflowKey`, `RunState`, `GateKind` (twelve kinds),
   `Severity`/`FindingKind`/`DispositionKind`/`DispositionStatus`, `ClaimVerdict` (frozen seven-value
   enum, REQ-OBJ-17), `ObligationState`/`ObligationSource`, `Anchor` (§11.3 verbatim — REQ-OBJ-16),
   `Rigor`/`ModelTier`/plan tiers per REQ-SPEC-2; the **sidecar schemas** (`findings.json`,
   `01-claim-ledger.json`, `rubric.json`, `structure-plan.json`, `response-ledger.json`,
   `cut-list.json` — REQ-SPEC-12); the §12.5 event payload schemas with the visibility split and the
   280-char free-text bound (REQ-DATA-37); `notes.ts` templates (REQ-ARCH-14); mobile-facing
   contracts' shapes deferred (1.x) but `FindingView`/`GateView` shapes per §5.7/§10.5 included since
   the beta's phone-width-shared surfaces consume them; **the analytics event catalogue schemas** —
   design/9 §7.2 (open it; adopted by reference, §0.1) with the §3.5 additions and the standard
   envelope, plus the REQ-BETA-6…12 event shapes (`reason_code`, `revision.move_traced`,
   `rereview.lineage`, `round.completed`, `surface.dwell`, `draft.imported`, `wtp.recorded`,
   `credits.exhausted_prompt`) — so every later emitter (PRB.03/05/06/08/12) consumes one schema
   set and none authors its own.
2. **`packages/db`:** Drizzle schema + forward-only SQL migrations for every §11.4 table; the §11.4
   SQL invariants verbatim (one working head per project; immutability trigger; obligation
   transition trigger; `claim_sources`; gate conditional-update shape; `credit_balances` as a table
   with the same-transaction maintenance rule; hold row-lock recipe as a documented helper); RLS:
   `FORCE ROW LEVEL SECURITY` on core tables, tenant set **only via `SET LOCAL` inside the
   transaction wrapper in `packages/db`**, a lint forbidding raw `SET app.tenant_id`, limited roles
   for `collab` and the harvester (REQ-DATA-4 amended; REQ-ARCH-25).
3. **`artifactPolicy`:** the §8.2 policy table in code (level + reasons + editMode per kind), seeded
   on deploy with `agent_types` and `protocols` rows (REQ-DATA-3); the REQ-SPEC-14 contract test:
   `keys(artifactPolicy) ≡ ArtifactKind ≡ the §8.2 row set` (63, incl. pre-registered
   `preference_profile`; obligations add **no** kind — REQ-OBJ-7).
4. **Seed** built from the three real projects (drafts, dossiers, ledgers, voices) for CI migrations
   and later fixtures (REQ-DATA-3); migration test for `backlog_items` → `source='agenda'`
   obligations (REQ-OBJ-7).
5. **Vocabulary lint bedrock:** the Appendix D.2 reserved/banned string table checked in as data;
   the i18n/contract-enum lint that later UI tickets extend (REQ-PROD-6, REQ-SPEC-2, REQ-BILL-18).
