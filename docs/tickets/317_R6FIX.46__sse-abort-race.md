## Defect

Cloud Run logs at 17:35Z and 16:14Z (2026-11-24): `TypeError [ERR_INVALID_STATE]: Invalid
state: Controller is already closed` thrown inside `RunEventStreamer.sink`
(`sse-routes.ts` → `event-stream.ts:163`), immediately followed by Cloud Run
"malformed response / connection error" **503s on `api.rhema.tools/projects`** and **500s on
`rhema.tools/p/:slug` SSR** — the web host's `listProjects` twin call hit the 503ing api.

Mechanism, two stacked seams:

1. `streamRunEvents` discards wakeup pump promises — `void streamer.pump()` in the
   subscriber callback and the poll interval, `void streamer.ping()` in the ping interval.
   When the client disconnects mid-pump, the route's sink calls `controller.enqueue` on the
   closed controller → synchronous `TypeError` inside the pump → `pump()` rejects → the
   discarded promise escapes every catch chain (the OBS.1 `.catch` wraps only the outer
   `streamRunEvents` promise) → **unhandled rejection → response abort → Cloud Run 503**,
   taking concurrent requests on the instance down with it.
2. Client aborts are constant — every EventSource reconnect, tab nav, and page reload closes
   an SSE stream. The R6 funded leg reloads every 25s during a ~30min run; each reload is a
   candidate abort. The defect fired at least twice inside one afternoon (16:14Z, 17:35Z)
   and blocked R6's green console-gate evidence both funded attempts.

## Fix

- `apps/api/src/sse-routes.ts` — the sink's `controller.enqueue` is wrapped in try/catch:
  a closed controller means the chunk is undeliverable (the client is gone), so the chunk
  drops and the pump continues; the abort listener still tears the tail down.
- `packages/orchestrator/src/event-stream.ts` — the tail promise now carries a reject arm:
  bus-subscribe, poll, and ping wakeups route `pump()`/`ping()` rejections into `done(err)`,
  which clears intervals, unsubscribes, and rejects — reaching the route's OBS.1 `.catch`
  (logs `sse_stream_failed`, errors the stream so EventSource reconnects). An abort still
  resolves cleanly; a synchronous `ping()` sink throw is caught at the call site. Function
  declarations hoist `done`/`wake`/`onAbort` above the interval consts so a synchronous
  `subscribe` wakeup can't hit the TDZ.

## Regression tests

`event-stream.test.ts` gains two cases in the composed-loop describe:

- a throwing tail sink during a bus-wakeup pump rejects the `streamRunEvents` promise
  (previously an unhandled rejection);
- an abort landing while a wakeup pump is in flight still resolves the tail cleanly
  (no hang, no spurious rejection).
