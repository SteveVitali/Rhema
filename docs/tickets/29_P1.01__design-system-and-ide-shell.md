## Goal

Replace the beta's flat shell (REQ-BETA-21 stopgap #2 — `packages/ui/src/shell.tsx`,
`renderToStaticMarkup` pages) **on the IDE routes** with the §5.1 seven-region pane layout, and
land the complete §5.9 design system underneath it: both themes fully defined, the pinned-light
paper policy, the typography and motion rules, the full state catalogue, and the WCAG 2.2 AA
baseline every later P1 surface inherits. Workspace-scope routes (`/app`, `/app/voices`,
`/app/inbox`, settings) may keep the flat shell until their own P1.* tickets land — the pane
system is for `/p/:project…` — but they must already consume the finished token set so the two
scopes never disagree on color.

## In scope — Stage A (code + tests, PR-able)

1. **The §5.9 token set, complete, in `packages/tokens`.** Every row of the spec's `:root`
   block: shell/paper surfaces, fg tiers, accent, the five severity and six kind hues, the four
   state hues, the 4-pt spacing scale and radius 4/8/12. The `[data-theme="light"]` set is a
   real theme — every token defined, hues re-tuned — and `[data-paper="light"|"dark"|"follow"]`
   implements paper pinning inside either shell theme. No pure black or white anywhere.
   **Contrast invariants as unit tests** over the token table: shell body ≥ 7:1, paper body
   ≥ 10:1, chips ≥ 4.5:1, non-text marks ≥ 3:1 — computed, not asserted by eye.
2. **Theme policy (REQ-IDE-38 amended; ledger D22; R17).** App theme Dark (default) · Light ·
   Auto, detected on first run, remembered per user, identical landing → app (REQ-GROWTH-2's
   token half: one token set is the single source — the landing page itself is P1.17). **No
   flash of the wrong theme:** the boot script resolves and stamps `data-theme`/`data-paper`
   before first paint. Paper theme pinned Light (default) · follow app · pinned Dark, per
   project (`projects.paper_theme`, default `'light'`, already in the §11.4 schema), toggled
   with `⌘⇧L`; the pinned-light paper renders inset with a 1-px border and shadow so it reads
   as a sheet.
3. **Typography (REQ-IDE-39).** Paper body Literata 17 px / 1.55 (Lora fallback; serif preset,
   default) or Inter 16 px / 1.55 (sans preset — the only other choice); heading weights 600 at
   2.0 / 1.625 / 1.375 / 1.125 em; paragraph spacing 1.0 em, no indent; shell UI Inter
   13/14/12 px with tabular figures for counts and credits; JetBrains Mono 13 px for citation
   keys and diff hunks; reader size stepper ±2 px, three steps, persisted; print/export
   11 pt / 1.4, 6.5 in measure. Wire the font loading so the choice is the preset, not ad-hoc
   family stacks.
4. **The pane system (REQ-IDE-8).** Exactly the seven regions — Rail (56 px, never hides except
   Focus; carries the project switcher and the Inbox badge slot), **Files** (the Browser;
   collapsed to a 36-px icon strip by default, `⌘1`), Page (always visible), Margin (visible
   only when the open version has findings; ticks-only below 1280 px), Timeline (`⌘2`), Desk
   (bottom drawer, closed by default; auto-opens on Live feed when a run starts, `⌘J`), Status
   bar. **Yield order as a pure, tested function of viewport width**: Browser opening below
   1,600 px collapses the Margin to ticks; below 1,600 px the Timeline is an overlay while the
   Browser is open and is otherwise the last pane to yield; below 1,280 px Margin → ticks and
   Timeline → overlay; below 1,024 px single-column with the Timeline as a sheet; below ~768 px
   the IDE routes render the phone layout (reader-only Page + the §10.1 inputs — the phone
   surface itself is P1.19; this ticket owns the breakpoint + the fallback rendering, not the
   mobile inputs).
5. **Resizing and the Page clamp (REQ-IDE-9).** Files and Timeline carry drag handles with snap
   points; the Page never resizes below 45 ch or above 80 ch (68-ch target) — a drag that would
   violate the clamp collapses the adjacent pane instead. **Pane state is per user per project,
   restored on reopen** — local state, never in the URL (§4.2 rule); pick the persistence seam
   (localStorage is acceptable; the desk/pane arrangement must not survive into shareable
   links) and record it.
6. **Focus mode and the View menu.** `⌘⇧F` hides everything but the Page and finding ticks.
   `⌘⇧M` opens the one View menu — **Write · Read · Focus**, with *Finding cards* on/off and
   *Show suggestions inline* inside Write and Read; **Source is not in the menu** (1.x; review
   13 F46). `?focus=1` on a shared URL toggles Focus mode for reading links (§4.2).
7. **Progressive disclosure (REQ-IDE-10).** A `Default / On demand / Advanced` classification
   on every control the shell exposes, Advanced behind a persisted per-user disclosure;
   Advanced never gates a workflow. The Advanced set per §5.1: raw tokens, model tier and model
   names, memory-file lists, restore points older than today, Verbose feed density, Source
   mode. Ship the disclosure *mechanism* + the classification table; the contents arrive with
   the surfaces that own them.
8. **Motion (REQ-IDE-40).** Named, tokenized durations: streaming text 120-ms block fade +
   caret pulse; phase progress 160 ms; finding arrival 200 ms slide + one tick pulse; pane
   transitions 160 ms; approval countdown numeric-only, amber at 5 min. **No decorative motion
   on the paper, ever.** `prefers-reduced-motion` collapses everything to instant — test it.
9. **The state catalogue (REQ-IDE-41).** Designed states for: empty project (three entry
   cards + quiet serif title field), empty findings ("No review yet · Review v1 ≈ N cr"),
   streaming (block shimmer, live counters, "syncing" pill), loading (skeleton rows in the
   shell — **never spinners on the paper**), run failed (red card with phase, reason, partials,
   refund line, Resume), sync offline ("offline · n changes queued" pill), conflict (inline
   banner, never a modal), insufficient balance (button swap only), frozen version (lock
   banner). **The only blocking modal in the product is the Cancel-run confirmation** — encode
   that as a lint or a component-boundary rule, not a convention.
10. **Accessibility baseline (REQ-IDE-42).** WCAG 2.2 AA with AAA reading contrast (item 1's
    tests prove the contrast half); 2-px accent focus rings; no colour-only encoding (severity
    always pairs hue with weight/text); full keyboard operability of the chrome; findings and
    approvals as ARIA landmarks with `aria-live="polite"` (assertive for spend gates); text
    resizable to 200 % without horizontal scroll; the Desk findings table is designated the
    screen-reader surface (the table itself lands in P1.07 — the landmark wiring and the
    `aria-hidden`/`aria-describedby` contract for margin decorations are defined here).
11. **The host decision — record it.** §13.1 names React Router framework mode; the landed web
    stack is Hono SSR + `renderToStaticMarkup` + esbuild islands with `react-router` already a
    dependency (`StaticRouter` in `render.tsx`). **Ruling:** keep the Hono host (deployed,
    prod-verified) and mount the IDE as one hydrated React subtree at `/p/:project*` (a second
    esbuild entry after the editor's pattern); pane state lives client-side, data flows through
    `apps/web/src/data.ts` `DataSource` → `@rhema/api-client` exactly as the beta routes do.
    If the island mount demonstrably cannot carry the pane system, stop and record why rather
    than silently rewriting the app — a full framework-mode migration is **not** this ticket.
    Same-origin data routes only: the browser never holds provider keys or tokens beyond its
    session.
12. **Cutover rules.** The `/p/:project` route renders the IDE shell; deep links
    (`/p/:project/v/:n`, `/r/:run`, `/f/:findingId`, `/a/:artifactId`) resolve inside it and
    restore the user's last pane arrangement with the target focused (REQ-IDE-1's layout half —
    the URL scheme already exists). Beta-era flat project sub-pages keep working until their
    P1.* replacements land; nothing this ticket ships may 404 a route a landed ticket created.
13. `turbo build lint typecheck` + `pnpm test` green; `check:licenses` and
    `check:protocol-markers` clean; the vocabulary lint covers every new UI string (the pane is
    **Files**, the drawer is **Desk**, views are Write · Read · Focus).
