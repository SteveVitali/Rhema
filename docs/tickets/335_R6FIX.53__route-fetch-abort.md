## Goal

The 2026-11-25 06:23Z nightly (`45560244600`) died 19m in with an unhandled rejection:
`TargetClosedError2: "route.fetch: Request context disposed"` at `r7legs.js:1327` — the
`**/bff/p/*` GET-patch handler (`r7legs.ts:1394`) `route.fetch()`-ed while Playwright was
tearing the context down mid-navigation (`GET /bff/p/untitled-6`). Node's fatal unhandled
rejection killed the whole suite: **zero leg verdicts written**, so the D-SPAF discharge
bake is un-discharged. This is the same abort-race class as 317_R6FIX.46.

Fix: the route callback degrades on disposal — wrap the fetch/fulfill path so a
`Request context disposed`/`Target closed` rejection becomes `route.abort()` (or continue),
never an unhandled rejection. Follow Playwright's own hint (`unrouteAll({ behavior:
'ignoreErrors' })`) where teardown ordering is the cleaner fix — but the callback guard is
the load-bearing half since route handlers are registered per-leg.

**Also recorded (same ticket, docs only):** the crash's Playwright call-log dumped the
fixture session cookie into the public CI log (`__Host-rhema.session_token=2dmJS…`,
test-tenant session — low value but a live credential in a public repo's log). Note the
exposure + add the scrub note; a full request-header redaction policy for Playwright
errors is out of scope → deferral if warranted.
