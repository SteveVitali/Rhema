## Goal

F-R7UX.8-1 (OPEN FINDINGS): the egress-proxy `RegionInstanceGroupManager` carries no
`updatePolicy` → GCP defaults to `OPPORTUNISTIC` → a template change from `pulumi up` (the
image repin every preview bring-up performs) **never rolls the running VM**. Observed twice
(pr-425, pr-426): the proxy VM kept serving the deleted hello-world template on :8443 —
HTTP-200 non-Message bodies → run agent phase "JSON but not a Message" failures. In-run fix
both times: manual `update-instances --minimal-action replace`. The finding's owed guard:
verify `list-instances` template after every image-pin `up` (or pin PROACTIVE).

Fix — the declared roll posture, not script machinery: `updatePolicy` on the MIG:

- `type: "PROACTIVE"` — the MIG brings instances to the target version on every update;
  `pulumi up` alone converges the proxy, no post-up verify step needed.
- `minimalAction: "REPLACE"` + `replacementMethod: "SUBSTITUTE"` — a template change needs a
  new instance, built with a fresh name.
- `maxSurgeFixed: 1` + `maxUnavailableFixed: 0` — **zero-gap roll**: the substitute joins and
  health-checks (autoHealing `initialDelaySec: 60`) before the old instance drops. Run pods'
  fail-closed egress never sees a dead backend — prod posture improves, not just previews.
