## Defect

`packages/protocols/parsers/draft-ledger.ts` read `Number(cells[0])` — real `04-draft-ledger.md`
`## Sections` tables ordinal the `#` column in Roman numerals (`I`…`XVIII`), so the parser kept
1 of 17–18 rows and `draftedSectionCount` undercounted (the `draft_sections_eq_plan` predicate +
`section.drafted` event source read the same rows). D-R7DEM.2c-1 re-homed the fix to BL-100.

## Fix

- `parseOrdinalCell`: `#` cell accepts an integer literal or a strict Roman numeral
  (`/^M{0,3}(CM|CD|D?C{0,3})(XC|XL|L?X{0,3})(IX|IV|V?I{0,3})$/` + subtractive-pair evaluation) →
  the integer plan-order index. Non-ordinal cells still skip; sort order and downstream consumers
  unchanged.
- New `packages/protocols/parsers/draft-ledger.test.ts` — the exact verification the deferral
  specified: an 18-row Roman `#` table parses every row integer-ordinaled and
  `draftedSectionCount` agrees (9 drafted of 18); integer + mixed/invalid cells pinned too.
