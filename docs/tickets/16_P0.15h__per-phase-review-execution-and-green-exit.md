   `/editorial-review\nphase=<skillPhase>\n…` (craft = `skillPhase "4"`). Live, the CRAFT phase agent exited 0 but

   stray `probe.txt`, so `artifact_nonempty(04-craft-notes.md)` failed and the phase never committed (the run
   failed with only intake committed). The single-phase-at-a-time invocation of the multi-phase editorial-review
   skill is not producing later phases' artifacts. This needs skill-integration reconciliation — inspect the real
   SDK message transcript for a resumed phase and the skill's per-phase behavior (does it need the prior phases'
   dossier as context / a `scope` input / a different phase signal?), and align the harness invocation + the
   manifest inputs + the skill so each phase produces its declared `artifacts[]` under the writable `output_dir`.
   Intake (skillPhase "0") already works green — the fix is for phases 1–6.

   phase.budgetShare × maxUsdPerRun` with `maxUsdPerRun = DEFAULT_MAX_USD_PER_RUN (10)` gives craft only
   `0.12 × 10 = $1.20`; the opus/`balanced` tier hit `Reached maximum budget ($1.2)` mid-phase. `DEFAULT_MAX_USD_
   PER_RUN` is HARDCODED (`runspec.ts`) with NO env override (`apps/api` never sets `runSpecConfig.maxUsdPerRun`).
