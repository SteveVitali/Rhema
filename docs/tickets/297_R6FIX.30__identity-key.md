## Item

Non-prod identity-shim callers fetch `rhema-<stage>-identity-headers-key` out of band each run
(`run-live-exit`'s `RHEMA_IDENTITY_KEY`, `res1-probe`/`research-probe-live`'s
`PROBE_IDENTITY_KEY`) — the operator read it from Secret Manager by hand. The BL row asks for a
`scripts/live` helper wrapping the `gcloud secrets versions access` fetch in the
never-argv/log/repo pattern.

## Fix

`scripts/live/identity-key.mjs`:

- `identity-key.mjs <dev|pr-<n>>` — captures `gcloud secrets versions access latest` and writes
  the value to stdout only, for the callers' `VAR="$(…)"` env-substitution contract.
- `identity-key.mjs <stage> --var <NAME> -- <cmd…>` — injects the value into the child's env
  (spawn env only; never an argv element, never a log line, never a file).
- **`prod` refused** — the shim is never armed there (AGENTS gotcha 4); the named secret does
  not exist, so the helper fails honest rather than gcloud-erroring. Only `dev` and `pr-<n>`
  mint `rhema-<stage>-identity-headers-key` (pulumi `index.ts` ~:422).
- `ē`-safe entrypoint guard (infra/AGENTS.md gotcha 9: `fileURLToPath` ↔ `resolve(argv[1])`).

Callers' doc headers updated to name the helper (`run-live-exit.ts`, `research-probe-live.ts`).

## Evidence

  refused), secret-name mapping, and a source pin that the value can only leave via env
