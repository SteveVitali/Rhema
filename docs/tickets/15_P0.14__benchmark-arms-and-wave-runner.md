## Goal
The §18 program's execution layer: the six arms as runnable configurations, blind normalization of
arm outputs into the common finding schema, the human matching/adjudication tooling (the one new
build §17 names), LLM-judge hardening for secondary metrics, pre-registration hash-commits, and the
wave runner + report.

## Load
- Spec §18.2 (six arms; steelman rules; no eval-only tuning of Rhema arms), §18.3 (REQ-EVAL-7…11;
  C-a…C-g binding), §18.4 (REQ-EVAL-15 criterion as the report's headline computation; REQ-EVAL-16
  consequence log; REQ-EVAL-17 cadence hooks), §18.5 (publication checklist: what is public vs

## In scope — deliverables
1. **Arms as configs:** A1 steelmanned one-shot frontier (prompt versioned, published-with-results
   flag, best-of-two candidates, native search, max reasoning; re-steelman per wave); A2 iterative
   generic recipe; A3 Grammarly-class (craft metrics + FP rate only); A4/A5 Rhema Standard/Full
   board on the production engine at pinned `protocol@version` + config-hash per run (REQ-EVAL-20);
   A6 human-editor intake path (results entered, not executed).
2. **Normalization (REQ-EVAL-7):** de-branding, extractor blind to arm, verbatim-substance rule
   (segment and locate, never sharpen), extraction-fidelity sampling audit (10%).
3. **Matching/adjudication tooling (REQ-EVAL-8):** blind-to-arm human matching UI/workflow for
   material-issue recall, FP validity (`valid-but-missed-by-gold` novelty vs `invalid`), novelty
   confirmation, post-revision pairwise preference (both orders); automated matchers suggest only;
   senior-adjudication records.
4. **LLM judges, secondary only (REQ-EVAL-9):** cross-family vs every arm judged; position-swapped
   pairwise with disagreement = tie; anchored rubrics with exemplars; per-unit scoring with length
   reported; per-wave calibration vs the human subset with the κ ≥ 0.6 disqualification gate;
   C-a…C-g implemented as report-blocking checks.
5. **Pre-registration (REQ-EVAL-10):** freeze + hash-commit of arms/configs/corpus manifest/metrics/
   matching+exclusion rules/analysis/criterion before a scored wave; deviation log; dev set exempt.
6. **Wave runner + report:** runs all arms over a wave manifest, drives scoring (P0.13) and
   adjudication, computes the twelve REQ-EVAL-11 metrics (headline reference-based, never
   pairwise), the REQ-EVAL-15 LIFT readout, stability bands; the REQ-EVAL-18 public/private split
   enforced by the report generator; the REQ-EVAL-16 consequence log.

## Out of scope (do NOT do here)

- Running the pilot wave (P0.15's exit work) and wave 1 (post-corpus milestone).
- Any marketing surface (REQ-EVAL-19 binds copy elsewhere).

## Acceptance criteria
- [ ] End-to-end dry run on the dev set: all six arms executable (A6 via intake), outputs
      normalized, matching workflow exercised, all twelve metrics computed, report renders with the
      public/private split (nothing private in the public artifact). *(agentic — one dev-set pass;
      the pre-registered pilot is P0.15)*
- [ ] Blind-normalization test: extractor receives de-branded input; a branded fixture is rejected.
      *(deterministic)*
- [ ] Judge gates: a judge below κ 0.6 on the calibration subset is disqualified and its metrics
      withheld; position-consistency reported; same-family judge/arm pairing rejected (C-a…C-d).
      *(deterministic)*
- [ ] Pre-registration: a scored-wave run without a matching hash-commit refuses to produce a
      report; post-freeze config drift is logged as a deviation. *(deterministic)*
- [ ] Headline path contains no pairwise metric (REQ-EVAL-11). *(deterministic)*
- [ ] Rhema arm runs record engine build + `protocol@version` + config hash, joinable to run-ledger
      metering rows (REQ-EVAL-20/14). *(deterministic)*
