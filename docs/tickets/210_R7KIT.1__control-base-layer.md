## Goal
Every native `button`, `input`, `select`, `textarea`, checkbox, radio and file control renders on theme tokens, with hover, active, disabled, keyboard-focus and invalid states, in dark, light and Auto. The "white system button on a dark shell" class disappears everywhere at once, on SPA and SSR documents alike. The undefined diff and state tokens exist with contrast tests. Route changes stop painting a focus box on the page heading. This ticket only styles the native controls. They stay the permanent no-JS/SSR fallback; the primitives arrive with 225 R7KIT.2.

## In scope — deliverables
1. Add `color-scheme` per theme (dark default, light, and Auto via the existing theme mechanism). Add token-based base rules for every native control class and state listed in REQ-KIT-1, emitted by the tokens CSS generator so they reach SPA shell and SSR documents. The specificity must lose to the existing IDE-region rules and to any existing inline style. (REQ-KIT-1) [UXC-14, A2, B7, C10, D3, D8, E1, G6, I1, I3]
2. New tokens `--fs-*`, `--radius-*` (the off-scale values R6 §8 counted resolve onto the scale or a named pill radius), `--paper-diff-add` / `--paper-diff-del` per paper theme, and `--state-ok`. Repoint the `--sev-ok` consumers to `--state-ok`. Each new colour token gets a contrast-floor test on its ground. (REQ-KIT-1) [UXC-31, UXC-32]
3. Programmatic route focus moves to the heading with no visible ring. Keyboard focus keeps the 2-px ring, so the REQ-IDE-42 / REQ-UX-7 focus-return behaviour is preserved. Cover it with a DOM test that tells programmatic focus from keyboard focus. (REQ-COPY-7) [A4, D7, C10, B15's heading box]
4. A unit test asserts the emitted stylesheet carries `color-scheme` and a rule for each control class and state. A DOM test renders a raw control in dark and light and reads the computed `color-scheme`, background and border tokens.
