## Defect

Intermittent zero-coverage skeleton dossiers on real, checkable text. Every claim row
delivered verbatim `unverifiable` + the note "Checkpoint skeleton row — research pending
this session." with zero sources → `citation_completeness{cited:N, covered:0}` →
`run.unverified` + `cost.refunded{zero_coverage}` (REQ-SPEC-31).

Diagnosis (corrected 2026-11-24; earlier read as a uniform post-10-28 regression — R6 run 1
`01M877J3` researched 15/15 on the same fixture, same prod SHA):

- The research path works: R6-1 spawned 9 verification subagents over 787s and wrote real
  verdicts with 3 sources per claim; the skeleton deliveries ran the phase shallow (R6-2:
  2 subagents / 384s / 27 requests) and closed on pure placeholders.
- **Gate hole:** `unclosedClaimOrdinals` (`apps/run-task/src/work-reader.ts`) counted ANY
  non-empty `note` as an evidence trail. RES.3's `checkpoint_contract` tells seats to write
  skeleton rows early — and seats attach a placeholder note. A never-researched row
  therefore satisfied `claim_ledger_closed` (review.ts / fact_check.ts manifests) and the
  phase legally `done`-ed. Whether a run delivered real coverage or skeletons depended on
  seat behavior, not the pipeline.
- The SKILL text carried the same loophole — "a `note` saying why it cannot be checked"
  is satisfied by a note that merely declares the row pending.

## Fix — three layers

- `apps/run-task/src/work-reader.ts` — `PLACEHOLDER_NOTE` regex (`pending research`,
  `research pending`, `checkpoint skeleton`, `placeholder`, `not yet
  researched|verified|checked`, `todo`, `tbd`): a matching note no longer counts as an
  evidence trail. Sources/urls still close a row regardless of note text.
- `packages/orchestrator/src/runspec.ts` — the `checkpoint_contract` now states that an
  un-researched skeleton row carries verdict `unverifiable` and nothing else (no note /
  url / accessedAt / sourceCheck / sources) until it is researched.
- `packages/protocols/skills/editorial-review/SKILL.md` — the Closure paragraph now names
  the pending-declaration as a placeholder that reads unclosed the same as a bare row.
  Protocols trio changed → `PROTOCOLS_VERSION` re-frozen `0.4.0+e922c281a6830f49` →
  `0.4.0+a04a14c64f4ec9a7` via `scripts/compute-protocols-version.mjs --write` (43 files).

## Regression test

`work-reader.test.ts` — a ledger mixing a `verified` row, three `unverifiable` rows carrying
pending-declaration notes ("Checkpoint skeleton row — research pending this session.",
"research pending", "not yet researched"), and an `unverifiable` row whose placeholder note
is backed by real `sources` yields `unclosedClaimOrdinals == [1,2,3]` — placeholders read
unclosed; an evidence-bearing row still closes. The justified-`unverifiable` closing cases
(a substantive note IS a disposition) still pass.
