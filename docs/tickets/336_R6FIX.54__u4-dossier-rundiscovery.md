## Goal

The 2026-11-26 06:23Z nightly (`45767836181`) — the first suite-complete run since
335_R6FIX.53's crash fix — failed one leg: `U4.controls` → `dossier
(/p/jrn-4fcbfc1a8d40-tenanta/review/): landed the NotFound leaf — the surface path
drifted`. Diagnosis: the leg's dossier-runId discovery fetched
`/bff/p/<slug>/timeline` with a **bare Node `fetch`** — anonymous, no session → 401 →
`runId=""`. It also parsed a `twin.runs[]` flat shape the TimelineDto twin never returned
(`rounds[].runs[].card.state` + `ungrouped[]`), so even an authenticated read would have
found nothing. For the leg's whole life the dossier surface navigated to
`/p/<slug>/review/` — the NotFound leaf, which is *control-clean* — and passed vacuously
until 315_R6FIX.44's h1 "Not found" guard (added 2026-11-24) turned the silent pass into
the honest failure. The NotFound-leaf path guard `path.includes(":runId")` could never
fire: `.replace(":runId", runId)` consumes the literal first.

Fix (all three arms):
- `page.request.get` — the APIRequestContext bound to the browser context carries the
  session cookie the tenant twin requires.
- `dossierRunIdFromTimeline` (exported from `u4-probe.ts`) parses the twin's real shape:
  `rounds[].runs[]` + `ungrouped[]`, state on `card.state`; first `completed`, else first.
- The owed-run guard checks `surface.path.includes(":runId") && runId === ""` **before**
  substitution, so a missing runId reports "no dossier run id discoverable" instead of
  navigating a malformed path.
