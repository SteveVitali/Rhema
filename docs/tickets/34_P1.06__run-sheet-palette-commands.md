## In scope — Stage A (code + tests, PR-able)

1. **One grammar, one parser (REQ-CHAT-21; ledger G22).** A shared module — new
   `packages/commands` or a `commands.ts` in an existing package (pick + record; it must be
   consumable by web client *and* server) — parsing `/<verb> [@scope …] [--lever value …]
   [free text → guidance]` into a structured command `{verb, scopes[], levers{}, guidance}`.
   The verb table covers the §7.2 MVP verbs (`/draft` `/review` `/revise` `/factcheck`
   `/research` `/outline` `/visualize` `/update-voice` `/export` `/compare`) with each verb's
   allowed scopes/levers; 1.x verbs parse but resolve disabled-with-reason. Scopes: `@v3`,
   `@v3 §II`, `@section:"…"`, `@selection`, `@outline`, `@review:vN`, `@finding:vN/m`,
   `@claim:vN/n`, `@figure:…`, `@thread`. Levers: `--rigor`, `--tier`, `--stage`,
   `--no-discourse`, `--no-second-read`, `--no-factcheck`, `--wait`, `--auto` (1.x rows marked).
   Unknown verbs are corrected against the table, never guessed; `--flag` input is accepted and
   converted to chips by completion, but **`--` never appears in any rendered surface, help
   card, or empty-state chip** — assert it.
2. **The structured row.** Typing `/` opens the structured row: verb → scope pill (menu-picked)
   → lever chips → free text. Four surfaces produce an **identical** run sheet from one parsed
   command (REQ-CHAT-22): the palette, the selection popover (*Ask · Visualize · Fact-check ·
   Review this section* — Line-edit/Cut marked 1.x), the artifact/Timeline context menu, and
   the chat composer (P1.11 consumes this same package — the seam lands now, the composer is
   not in this ticket).
3. **The `⌘K` palette (REQ-IDE-49; REQ-CHAT-28).** Sections: *Run* (the state function's next
   step pinned first with its estimate, then verbs), *Go to* (artifacts, sections, findings by
   number — rides P1.04's search endpoint), *Recent runs*, *Threads*, *Settings*. Cost-bearing
   verbs always open the sheet; **the palette never launches a run**. `?` opens the cheat
   sheet. Wire the full §5.12 keymap — `⌘1`/`⌘2`/`⌘J` (P1.01 panes), `⌘⇧M`/`F`/`L`/`T`, `⌘S`,
   `⌘⇧R` (run next step → sheet), `⌘⇧D`/`E`/`V` (verb sheets; `⌘⇧A` stays reserved), `⌘G`,
   `⌘I`, `⌘,`, `⌘⇧C`, `[`/`]`, `⌘Z`/`⌘⇧Z` — plus the findings chords **scoped to Margin /
   Findings-list focus only, inert while the caret is in the Page** (the chord behaviours land
   with P1.07's surface; the keymap dispatcher + focus scoping land here).
4. **The two-tier sheet (REQ-IDE-13 amended; REQ-PROD-5).** Top tier: title line ("Review v2 ·
   5,180 words · 21 claims"), the **Rigor** control — Quick · Standard · Full board with each
   notch's one-line consequence copy — the dollars-first estimate box ("≈ $5.60 · never more
   than $8.40" + the second line's credits/cap/balance-after + ⓘ "Why this estimate?" lever
   breakdown), and the button. One collapsed row summarises Protocol · Venue · Stage · Voice ·
   Model tier · Guidance and expands to the full sheet: protocol/venue/stage/voice fields, the
   guidance box (+ "N standing notes apply"), Model tier (Base / Balanced / Frontier with
   multipliers; model names in small type — **Advanced-only**), Advanced phase toggles each
   showing a **signed credit delta from the same estimator** (REQ-BILL-5), Budget cap
   (editable upward only), Approvals policy (Named approvals / Wait for me at each / Run to
   completion), and "Don't ask me to confirm runs under N credits" (max 1,000). Variants stay
   hidden (1.x). Model tier is never a first-class control — §4.3's four-choices rule.
5. **The estimate lifecycle.** On open, an immediate provisional estimate from word count × the
   protocol's claim density ("≈ $5.60, refining…"); the cached claim-count pre-pass refines in
   place ≤5 s (PRB.03 landed the estimator — verify the in-place refine; the Run button is
   **never** disabled waiting, and a launch before the pre-pass returns caps from the
   provisional). Every lever change recomputes estimate/cap/time ≤100 ms via
   `POST /estimates` (stateless, cached — REQ-SPEC-16). `cap = ceil(1.5 × estimate)` →
   `max_usd` + `hold`. Consent: `>500 cr` or `>200 cr and >25 % of spendable` → "Confirm and
   run" second click; the per-user override (≤1,000) removes it (REQ-BILL-4 amended).
   Insufficient balance → the resolution panel (lower rigor · Base · fact-check off · add
   credits/upgrade — cheapest fitting option primary + the plan that would have covered it).
   Launching on the working head promotes it first ("will be promoted to v(N+1)"). Obligation
   scope lines render on the sheet's scope card ("4 open obligations will be checked" / "this
   run addresses 7 open obligations") — the REQ-OBJ-6 stamp itself is P1.08's; the sheet
   surface for it lands here.
6. **Trial rendering (§14.3/REQ-SPEC-8's sheet half).** An entitlement-eligible Review sheet
   shows **Included** in place of the estimate box — no dollars, no cap arithmetic, no consent
   click; Balanced/Frontier and Full board render locked with prices; >6,000-word trials offer
   "review the first 6,000 words, or upgrade".
7. **Scoped runs (REQ-CHAT-23/24; ledger G22).** `scope` is a first-class run input end-to-end:
   the command's `@scope` lands on `POST /runs {scope}` → `runs.scope`; the sheet shows the
   scoped estimate **beside** the whole-draft estimate; scoped dossiers stay keyed
   (version, run) and labelled with their scope (the section-letter rendering is the findings
   surface's — the keying/label lands here). **Concurrency ruling (record it):** the PRB.21
   guard relaxes from per-project to per-write-lock — read-only runs (review, fact-check,
   research) may run concurrently, including scoped ones; a writer-run (draft, revise) still
   excludes any second writer of the same draft per §6.3 "never two writers of one draft". If
   scoped-run parallel semantics turn out to need lock-set granularity the schema doesn't
   carry, keep the conservative guard and record a `D-P1.06-*` row instead of shipping a race.
8. **Confirm scope surfacing (REQ-SPEC-17's sheet half).** The sheet reflects the scope-approval
   policy: informational by default at Quick/Standard; blocking (2 h, proceed-as-proposed) at
   Full board, on protocol/venue change, or under *Wait for me at each* — the run card's card
   itself is P1.05's; this ticket surfaces the policy + its consequence at launch.
9. `turbo build lint typecheck` + `pnpm test` green; the REQ-GROWTH-16 lint
   (`AskButton`/`RunButton` only, estimate required) still enforced on the new components;
   vocabulary lint on the sheet/palette strings (Reserved: the three notches, the three tiers,
   the three approval policies — verbatim).
