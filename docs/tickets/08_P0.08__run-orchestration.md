# P0.08 — Run orchestration: lifecycle, internal API, queue, reaper, events

- **Sequence:** 8 of 50
- **Phase:** 0 — Foundations
- **base_branch:** current checkout (stacked PR chain)
- **Depends on:** P0.02, P0.06 (engine/image), P0.07 (proxy — provision mints its credentials)

## Goal
The durable run model: the §12.4 state machine in `api` + `worker`, the internal run API with
attempt fencing, provisioning (token + proxy credential + ECS RunTask), heartbeats and the reaper,
cancellation/retry classes, lock-set concurrency, and event persistence/streaming (SSE).

## Load
- Spec §12.4 end-to-end (state diagram; steps 1–10; resumability; cancellation/retries; concurrency
  and lock keys; steering-at-boundary; progress/ETA), §12.1 (service table: api/worker/run-task
  responsibilities), §6.3 (the project state function — this ticket implements it), §12.3
  (REQ-ARCH-9: model profiles validated against the phase-class capability table), REQ-ARCH-3/9/11,
  REQ-RUN-2/10–18, REQ-DATA-33/34/39/40/41, REQ-SPEC-16 (creation model — the estimate *service* is

  for sheet-less runs), REQ-SPEC-13 (completion-oracle evaluation), REQ-PROD-9/REQ-SPEC-3, §12.2

## In scope — deliverables
1. **State machine + transitions** exactly §12.4's diagram; transitions only by the orchestrator in
   a transaction that also appends the event (REQ-DATA-33); `estimating` does not exist.
2. **Run creation:** `POST /projects/:id/runs` (idempotency key, 24-h `(billing_account, key) → run_id`
   memo), input snapshot freezing (estimate, cap, rigor, model profile, phase set,
   `rate_table_version`, counts — REQ-BILL-6 row shape), **model-profile validation against the
   §12.3 phase-class capability table** (an override whose provider lacks the class's capabilities
   is rejected — REQ-ARCH-9), hold placement through a **hold/debit/release interface this ticket
   defines (signatures + a test stub); P0.11 supplies the sole real implementation** — no ledger
   writes here, `awaiting_consent` + `confirm_cost` gate for sheet-less runs (REQ-SPEC-16).
3. **Queue + locks:** pg-boss jobs (`run.start/resume/cancel/reap`), singleton keys — this ticket
   **registers** the `gate:<id>` job *type* only; scheduling and handler semantics are owned by
   P0.10; the §12.4 lock-key vocabulary (`draft:read/write`, `head:`, `corr:`, `ns:write:`,
   `persona:profile:write:`) enforced in Postgres with the permitted-overlap matrix
   (REQ-RUN-17, REQ-DATA-39/40); plan-concurrency admission at `queued → provisioning`.
3b. **The §6.3 project state function** as one shared module (ledger K8): the pure function of
   `(outline?, versions[], reviews[], responses[], runs[], accepted_version?, exports[],
   archived_at?)` → state key + suggested next, exactly the §6.3 table and pseudocode, with the
   `running`/`needs_you` overlays — consumed by PRB.01/P1.04/notifications/palette; no surface
   ever stores a `status` column (REQ-PROD-9; REQ-SPEC-3 in full).
4. **Provision:** run token (JWT 2 h; claims incl. **attempt**), per-run proxy credential + allowlist
   minting (consumed by P0.07), ECS RunTask with pinned image digest + STS session policy scoped to
   project/voice prefixes; 3 launch attempts with backoff (warm pool deferred to ops; p95 measured
   in P0.15).
5. **Internal run API** (`GET hydration`, `PUT heartbeat`, `POST events`, `POST steps/:key/commit`,
   `POST steps/:key/fail`, `POST audit`): run-token auth, every call carries `attempt`,
   `409 stale_task` below `runs.current_attempt`, token refresh on heartbeat, rotation per
   re-enqueue, revocation at terminal state (REQ-ARCH-11, REQ-RUN-15, ledger M14). No `POST fetch`.
6. **Heartbeats + reaper:** 20-s heartbeats to Redis (`SETEX`; Postgres sees transitions only);
   stale > 3 min → `orphaned`; StopTask-or-60-s-grace before next attempt; ≤2 re-enqueues per step;
   `resume_partial` after exhaustion.
7. **Phase loop:** `Engine.startPhase` per manifest order; completion-oracle evaluation
   (REQ-SPEC-13: SDK subtype + phase-result + predicates); retry classes by `error_class`
   (`infra`/`provider_transient`/`budget`/`artifact_missing`/`refusal`/`boundary`/`stale_task` —
   §12.4 semantics incl. provider-outage pause ≤2 h; the `egress.denied`-spike / `suspicious_query`
   run-pause reaction, REQ-ARCH-32); provisional `usage_records{sdk_stream}` from `usage.tick`;
   back-edge counting (`runs.replans`, cap 2) with re-open-Approve-plan signal to P0.10. State
   transitions are made in a transaction that also appends the event **via P0.08b's writer**
   (REQ-DATA-33).

## Acceptance criteria
- [ ] FakeEngine integration: a run traverses created→queued→provisioning→running→waiting_gate→
      queued→running→finalizing→completed with every transition event-paired in one transaction.
      *(deterministic)*
- [ ] Fencing: a commit/heartbeat/event from attempt N−1 after re-enqueue → `409 stale_task`; the
      task self-terminates (fixture). *(deterministic)*
- [ ] Reaper: killed heartbeat → `orphaned` → resume as attempt N+1 with rotated token; third
      re-enqueue opens `resume_partial`. *(deterministic)*
- [ ] Lock matrix tests: second writer queues with `running_run_id`; review(vN,A) ∥ review(vN,B)
      allowed (k=1/k=2); persona run locks the persona, not the project. *(deterministic)*
- [ ] Duplicate `POST /runs` with one idempotency key → one row. *(deterministic)*
- [ ] A model-profile override whose provider lacks the phase class's capabilities is rejected at
      run creation (REQ-ARCH-9). *(deterministic)*
- [ ] State-function table test: every §6.3 row (state key, pill, suggested next) reproduced from
      fixture row-sets, overlays included; no `status` column exists in the schema (REQ-PROD-9;
      REQ-SPEC-3). *(deterministic)*
- [ ] Completion oracle: a phase with `subtype: 'success'` but a failing predicate →
      `artifact_missing`, one guided retry, then failed-with-partials (fixture). *(deterministic)*
