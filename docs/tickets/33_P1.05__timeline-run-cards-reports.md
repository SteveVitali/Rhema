## Goal

The Timeline pane is the round log rendered as run rows: round cards (`vN` → review → revise →
`v(N+1)`), the next-step card on top, the three verbs. Run cards carry the full §5.5 state
table; the Desk's Live feed tab carries all three densities; the MVP steering primitives work
for real; and a finished run answers "what did I get" (the ≤200-word walkthrough) and "why did
it cost that" (the §14.5 level 3–4 run report).

## In scope — Stage A (code + tests, PR-able)

1. **The Timeline pane.** Newest-first list of round cards: `vN` chip → review run → revise run
   → `v(N+1)` chip; the **next-step card** above the newest round (the state function's verb +
   its estimate — REQ-CHAT-28's data half); the Outline chip (or "Imported draft") below the
   oldest; collapsed older rounds summarize "v1 → review (49 findings) → revise (14 moves) →
   v2". The three verbs — `[Draft ▾] [Review ▾] [Revise ▾]` plus `⌘⇧R` run-next-step — each
   open the run sheet (today's sheet surface; P1.06 swaps in the full pane sheet — keep the
   affordance, not the implementation, pointed at the verb).
2. **Run cards, all six states (REQ-IDE-11).** Extend `RunCardView`/the api projector so the
   card covers the §5.5 table: *queued* (position; "starts when Review of v2 finishes" / the
   slot-ETA range); *running* (phase list ✓/◐/○, live per-phase counters, elapsed, credits
   spent / cap, ETA band from `run_steps` history — ledger K4; the parametric model until 50
   samples exist); *waiting_gate* (the approval card + deadline); *completed* (one-line
   summary, deliverable chips — Letter · N findings · Claims N · Second read · Rubric — cost
   actual vs estimate, Run report link); *completed_partial* / *failed* (phase reached,
   partials listed, refund line, Resume); *cancelled* (as failed minus error). **No progress
   element derives from agent-authored text** — orchestrator-emitted state only.
   Opt-out/disabled phases render greyed "off" on the card and in the report (REQ-IDE-12).
3. **The Live feed Desk tab (REQ-IDE-14, full).** Three densities — *Summary* (phase cards
   only), *Details* (default: phase cards + `source.read`, `claim.checked` verdict chips,
   `finding.emitted`, `artifact.written`, `subagent.started/finished`, `check.result`),
   *Verbose* (every search query and fetch, blocked-domain notices, retries — **behind the
   Advanced disclosure**). Density is a menu on the tab, never a chord. The whitelist filter
   already lives in `feed.ts`; verify no event shape can carry prompt text, agent reasoning or
   private-memory content (REQ-DATA-37's mapper guarantee — assert it at the UI seam too).
   Provisional findings streaming into the Margin is P1.07 — the feed shows their events now.
4. **Steering, MVP rows (REQ-IDE-18 amended; REQ-GATE-12/13).** On a running card:
   **Pause** = *Pause after this phase* — the run commits the in-flight phase then parks at
   zero compute (`waiting_gate`-class park; the sandbox exits — reuse the `pauseRun`
   machinery's park semantics, but the user-initiated path is its own transition, not the
   refusal gate); the card shows *Paused after Verifying sources (3 of 8)* with Resume /
   Resume-with-a-note / Stop. **Stop…** = cancel keeping partials: committed artifacts
   retained and labelled `partial (3/6 phases)`, resumable; undelivered-phase debits refunded
   per the ledger rules. **Note for the next phase** = one text field → a
   `Guidance{source:'queued_message'}` row delivered at the next phase boundary, **never into
   independence contexts** (second read, fidelity audit, gap check — enforce at consumption).
   No section-granular pause, no delivery-point display, no batched inline comments — those
   are 1.x and the card must never promise them.
5. **The walkthrough (REQ-IDE-19 amended; ledger D20).** A completed run gains a ≤200-word,
   model-written walkthrough — what was delivered and the one thing to read first. **One
   package-class model call** at (or just after) delivery; its usage lands on the run's usage
   rows; on failure the run still delivers and generation retries lazily on first read.
   Persist the text on the run/deliverable; the card renders it (the Inbox's
   return-to-walkthrough behaviour is P1.19).
6. **The run report (REQ-BILL-8 levels 3–4; REQ-BILL-9; REQ-BILL-10).** At
   `/p/:project/r/:run#report` (and `/app/usage/r/:run` → redirect, §4.2): header (cost,
   estimate, cap, released, duration), **flags** computed server-side with the templated
   sentences (`fact_check_dominated`, `long_draft`, `discourse_map`, `second_read_model`,
   `over_estimate`, `under_estimate`, `retries` — the ≥20 %-of-cost / ≥25 %-of-estimate
   triggers), phase bars, **seat split with subagent labels** beneath each seat ("Editor ›
   Second read"), "what drove it" naming `cost_per_verified_claim.review` vs `.fact_check`
   distinctly, suggested guidance for the next round. Level 4 — the phase × seat × model-tier
   × credits × duration × searches × fetches table plus tokens-by-kind and provider usage
   ids — loads **only on Advanced disclosure open** (`RunReport.advanced` is a separate read
   model; `AccountUsage`/`ProjectUsage` never gain a `tokens` field). **No level exposes
   prompts, private memory, transcripts, or source-note bodies** — a contract test asserts the
   DTOs cannot carry them.
7. **Re-skin, don't fork.** PRB.04's flat dossier (`/p/:project/review/:runId`) keeps working;
   the Timeline/run-card surfaces consume the *same* findings-core view models and api
   projectors — extend them, never duplicate the derivation.
8. `turbo build lint typecheck` + `pnpm test` green; vocabulary lint (run-report strings:
   credits + dollars, never "tokens" outside Advanced).

## Acceptance criteria

- [ ] A fixture run in each of the six states renders its specified card (counters, credits vs
      cap, ETA band, deliverable chips, partial labels, Resume) with no agent-authored progress
      text — the card consumes only the orchestrator view model. *(deterministic)*
- [ ] Disabled phases render "off" on card and report (REQ-IDE-12). *(deterministic)*
- [ ] Feed densities filter exactly the §5.5 event sets; Verbose is unreachable without the
      Advanced disclosure; no event payload carries prompt/reasoning/private-memory content.
      *(deterministic)*
- [ ] Pause commits the phase then parks at zero compute with the "(n of m)" card and
      Resume/Resume-with-note/Stop; Stop keeps partials labelled + resumable with refunds;
      a queued note becomes `Guidance{source:'queued_message'}` consumed at the next boundary
      and is undeliverable into an independence context. *(deterministic)*
- [ ] The walkthrough is ≤200 words from one package-class call, stored on the run, retried
      lazily on failure. *(deterministic w/ fake engine; live observation optional per item 11)*
- [ ] The run report renders header/flags/phase bars/seat split/"what drove it"/suggested
      guidance; level 4 loads only on disclosure; a contract test proves no read model can
      carry prompts, memory, transcripts or source-note bodies (REQ-BILL-8/9/10).
      *(deterministic)*
- [ ] Stage B evidence in the run ledger; no new OPEN deferral without a `D-P1.05-*` id.
      *(operator-gated)*

## Notes

The walkthrough is deliberately one call, not a phase: it reads the delivered artifacts, not
the transcript. Keep its input whitelist narrow (letter/summary + artifact list) so it can
never be a memory leak vector.
