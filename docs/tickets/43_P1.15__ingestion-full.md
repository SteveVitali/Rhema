## In scope — Stage A (code + tests, PR-able)

1. **The provider framework.** A `packages/ingest` package (or `apps/worker/src/ingest/` — pick the
   boundary that keeps provider modules pure TS with the network behind an injected fetch port
   routed to `apps/fetcher`): `interface Provider { discover(conn): DiscoveredItem[]; fetch(item):
   {body, meta}; changeKey(item): string }` (REQ-INGEST-2). Discovery emits rows only — titles,
   dates, word counts, access — never bodies (assert: a discover pass makes zero body-endpoint
   calls).
2. **The five MVP providers.** **Substack public API**: archive endpoint → discovered items
   (`externalId` = post id/slug, `access` from audience), body endpoint on fetch, `/feed`
   fallback when the archive endpoint 404s, `changeKey` = `updated_at` else normalized body hash;
   `access≠everyone` → the item lists as *Paywalled — import your export* (never fetched, never
   credentialed). **Substack export zip**: `posts.csv` + `posts/<id>.<slug>.html` → the same
   discovered-item pipeline (the only lossless path for paid posts — the export CTA links here).
   **Single URL**: Readability-class extraction via fetcher→convert; `changeKey` =
   ETag/Last-Modified else body hash; paywall detected → *partial* + note. **Upload**/**Paste**:
   the existing PRB.10/PRB.20 path re-cast as connections without discovery (REQ-INGEST-1's
   "uploads/pastes are connections").
3. **Link-a-publication flow (REQ-INGEST-3/5/12).** Handle → fetcher-validated (SSRF guard) →
   `discover()` only → the review screen: per-item include/omit toggles (free included by default;
   paid/unknown omitted with the export CTA) → Confirm → `fetch` at ≤1 req/s, honest UA, robots
   honored → canonical Markdown → `Sample v1` per included item. A `Connection` row + its
   `DiscoveredItem`s persist before the first fetch.
4. **The Samples tab (REQ-INGEST-4's surface).** Sources left (per-connection status, last sync,
   error + remedy, Re-sync, remove) / Items right (per-item include/omit retaining bytes —
   extends PRB.10's toggle to discovered items — quality badge, ★ held-out badge post-calibration
   per P1.14, the "changed since profile" line feeding the pill); the corpus summary line;
   filter/sort by state/quality/date.
5. **Re-sync + diffing (REQ-INGEST-6/11; AC-I-A).** Manual **Re-sync** default; optional daily
   auto-sync (`connections.schedule`/`autoIncludeNew` columns exist — auto-sync never auto-includes:
   new remote items arrive as `state:'new'` awaiting confirmation). Diff by `externalId`:
   `new` / `removed_remote` (kept, badged, still included — remote disappearance never deletes
   bytes) / changed `remoteChangeKey` → conditional re-fetch → a new `sample_versions` row **only
   if** the normalized body hash differs (assert AC-I-A: timestamp bump, same body → zero new
   versions, no pill change). Provider errors surface the verbatim message + a remedy line; the
   last good version is always retained.
6. **The PDF pipeline (REQ-INGEST-7/8/9).** Convert's TS-native extraction + heuristics emits a
   quality verdict per file (`clean`/`reconstructed`/`partial`/`unreadable`/`empty`); non-clean
   opens the quality drawer: **Check side by side** (pdf.js renders the raw PDF beside the
   Markdown — the only place raw source is shown), **Re-convert with visual ≈180 cr** (the opt-in
   visual tier — estimate + cap shown before consent, runs as a priced worker-side model call on
   rendered pages), **Omit**. The small reconstruction pass (≈4 cr, priced before it runs) fixes
   extraction artifacts on `partial` verdicts; scans route through the OCR step first. Visual tier
   is never automatic — only from the drawer, only after the estimate.
7. **Canonical Markdown + preview (REQ-INGEST-10).** Every sample normalizes to the
   research/9-§4 shape: front-matter (title/date/source URL/fetched-at/original+content
   hashes/quality), `[^n]` footnotes, content-addressed images, no body H1. The item preview is
   read-only with version history — editing a sample makes it a different piece (a new
   connectionless item), never a mutation.
8. **Formats + caps (REQ-INGEST-8).** The full list above; enforcement is server-side (sniffed
   type, not extension); 25 MB/file, 200k words/sample, 50 files/batch — over-cap files stay
   listed, auto-omitted, counted against coverage, with the reason shown.
9. **Never-cookies (AC-I-B; REQ-INGEST-5).** No cookie/session-token field, header, or form input
   anywhere: CI grep over the ingestion UI, the `connections` schema surface (`authRef` stays
   unused at MVP — Ghost Content-API keys are 1.x), the OpenAPI document, and the client bundle;
   Substack connector fixtures carry no `Cookie` header. Paid/private content is only ever the
   export-zip path.
10. **Deletion (REQ-INGEST-14's ingestion half).** Deleting a voice cascades samples + raw bytes +
    the profile within the stated retention window via `apps/worker/src/deletion.ts`; forked
    house-style samples are references, not copies (assert no double-delete).
