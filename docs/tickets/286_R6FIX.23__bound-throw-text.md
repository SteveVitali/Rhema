## Defect (verified at 277_R6LOW.1; BL-124)

Three throw sites embedded unbounded/multi-line text in thrown Error messages that reach log group
headers: `ingest.ts` `convert job run failed` + `convert-svc refused` (upstream response-body
slices — 500/300 chars, newline-capable) and `run-sheet/profiles.ts` `run sheet: workflow "…"`
(interpolates `workflow`, which `run-routes.ts` casts from `body.workflow` — arbitrary request
text, the WorkflowKey type is no runtime bound).

## Change — decision the row scoped: keep bounded messages, don't drop to codes

The code comments establish the diagnostic intent ("a bare status hides IAM vs quota vs
API-disabled failures"), so the fix keeps the messages but makes every interpolation
single-line + capped:

- `ingest.ts` both sites: `detail` → `.replace(/\s+/g, " ").slice(0, 200)` — collapses any newline
  (no forged log lines) and caps at 200 chars reaching the thrown text.
- `profiles.ts`: `String(workflow).replace(/\s+/g, " ").slice(0, 64)` — the typed union was never
  a runtime guarantee (cast upstream); a forged `body.workflow` can no longer smuggle bytes into
  the thrown message.
