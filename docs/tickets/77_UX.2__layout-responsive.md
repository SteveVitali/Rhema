## Goal
The product looks designed at both widths the review walked: desktop 1440×900 and phone 390×844. The review
found (screenshots in `docs/build/reports/2026-09-30_prod-review/`):
- **PR-U5 — `/app/new` is unstyled at desktop** (`03-new-project-unstyled-shell.jpg`). The Files, Timeline and
  Desk panes are full-width stacked blocks, and the rail icons show as raw glyphs. Root cause, verified in code:
  - `NewProjectPage` wraps itself in `<IdeFrame>` (`apps/web/src/pages.tsx` ~961–990 → `IdeFrame` ~177)
  - the route's `renderNewProject` (`apps/web/src/server.ts` ~1605–1636) never sets `PageData.ide`
  - so `renderDocument` (`apps/web/src/render.tsx` ~67–76) emits neither `IDE_CSS` nor `/assets/ide.js`
- **PR-U6 layout half — pricing overflows at phone width** (`02-pricing-phone-overflow.jpg`). The comparison
  table puts 535 px of content in a 390 px viewport (`apps/web/src/marketing.tsx` ~336–345, a bare `<table>`),
  and the header is clipped.
- **PR-U7 — the phone project page** (`12-project-phone.jpg`):
  - the action row is wrapped, underlined text links (`pages.tsx` ~683–698, `<p style={{display:"flex"}}>` of
    `<a>`s)
  - the Page's sync pill is `position: fixed; bottom: 28px; right: 24px` (`packages/ui/src/page-editor.tsx`
    ~451–456) and floats over body text
  - most tap targets are < 32 px

This ticket owns journey step **P1**: project page, run sheet and pricing at phone width with no horizontal
overflow, and primary actions that are buttons ≥ 44 px.

## In scope — deliverables
1. **`/app/new` styled** (PR-U5; REQ-IDE-8).
   - Every route that renders `IdeFrame` gets the IDE stylesheet and island: fix `renderNewProject` (GET and
     POST paths), then audit the rest.
   - A structural test enumerates the routes, renders each, and fails if a document contains the `.ide` shell
     without `IDE_CSS`.
   - Owned decision: whether `/app/new` (a workspace-level sheet in §5.3, with no project) belongs in the IDE
     frame at all or in the workspace `Shell`. Record it in an ADR.
2. **No horizontal overflow at phone width** (PR-U6 layout; REQ-MOBILE-3 amended).
   - Pricing, the project page, the run sheet (whose phone form is the §10.1 blocked note) and every touched
     surface keep `document.scrollWidth ≤ viewport` at 390 and 320 CSS px.
   - The pricing matrix either restacks per plan at phone width or scrolls inside its own labelled container
     (owned decision; WCAG 1.4.10 exempts data tables, but the page itself must not scroll sideways).
   - The pricing header is not clipped.
   - Content and figures stay ACT.1's: this ticket changes layout only.
3. **Phone project page** (PR-U7; REQ-SPEC-20).
   - The action row becomes buttons: primary actions ≥ 44×44 px, every target ≥ 24×24 px (WCAG 2.2 SC 2.5.8),
     and spacing that prevents mis-taps.
   - The §10.1 split is kept (no run start, import, export or new project on phone), and no dead-end link
     (REQ-MOBILE-3).
   - The sync pill (the one EDIT.1 kept) sits in the phone bar or flow and never overlaps text.
   - On desktop it never overlaps the Desk composer or the status bar.
4. **WCAG 2.2 AA pass on touched surfaces** (REQ-IDE-42).
   - Surfaces: `/app/new`, pricing, the project page and phonebar, the run sheet's phone note.
   - Checks: contrast (AA; AAA on the reading paper), visible 2-px accent focus rings, full keyboard order, no
     colour-only state, labels and names on controls, target size, reflow at 320 px, and text resize to 200%.
   - An automated checker runs in the JOURNEY.1 phone and desktop legs. Tool choice is an owned decision:
     axe-core is MPL-2.0, which is not on `licenses.allowlist.json`, so it needs a dev-only
     `licenses.exceptions.json` entry with rationale or a permissive alternative.
   - Manual findings the checker cannot see go in the run ledger.
5. **Tests.**
   - SSR and CSS-seam tests: the IDE stylesheet on every `IdeFrame` route, the pricing matrix's phone rule, the
     phone action row rendered as `<button>`/button-styled controls with min sizes in the generated CSS, and
     the pill not `position: fixed` over the Page at phone width.
   - Each fails on the pre-fix code.
   - Extend `inbox-phone.test.ts`'s seam style.
6. **Stage B.** Deploy, then turn journey step **P1** green:
   - at 390×844: no horizontal overflow on the project page, run sheet and pricing; primary actions are buttons
     ≥ 44 px, clickable and unobscured; the pill overlaps no text
   - at 1440×900: `/app/new` renders styled, as a screenshot compared against the Stage A render
   - the accessibility checker reports zero AA violations on touched surfaces (or each violation is dispositioned)
