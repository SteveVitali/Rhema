## The chain this ticket closes (diagnosed live in P0.15f; each surfaces once the prior is fixed)
1. **D-P0.15f-1 — the harness cannot `setpriv`-drop to the agent uid** (`setpriv: setresgid failed: Operation
   not permitted`). The entrypoint drops root→harness (uid 10001); the harness (non-root, caps cleared on the
   uid change) then lacks CAP_SETUID/SETGID to drop harness→agent (uid 10002), so the agent exits 127.
2. **D-P0.15f-2 — the per-run proxy credential is never injected** into the agent's request. `injectProxyCredential`
   (`apps/run-task/src/proxy-injector.ts`) is a pure function with NO live caller; the agent points
   `ANTHROPIC_BASE_URL` straight at the egress-proxy and its scrubbed env forbids the credential → every request
   would 403 `egress.denied`.
3. **D-P0.06-1 — the first live SDK exercise is untested.** Once 1+2 are fixed the agent reaches the SDK for the
   first time on the wire; whatever surfaces there (SDK bring-up, the streaming path D-P0.07-5, the completion
   oracle) is diagnosed live WITH LOGS and fixed.

   HARNESS (uid 10001, the sole credential holder): it reads the credential from `PROXY_CREDENTIAL_FILE`, stamps
   `x-rhema-proxy-credential` (`injectProxyCredential`) on each request, and forwards to the egress-proxy
   (streaming, so SSE passes through). Point the agent's `ANTHROPIC_BASE_URL` at `http://127.0.0.1:<port>` (the
   injector), NOT the egress-proxy directly; the injector's upstream is the egress-proxy. The credential MUST
   NEVER enter the agent env/process (keep `scrubbed-env` forbidding it; assert it). Unit-test the injector:
   stamps the header, forwards the body+method+path, streams the response, and a request that bypasses it (the
   agent's own, credential-less) 403s at the egress-proxy. Wire it into `harness-main.ts` (start before the agent
   launch; the injector runs in the harness process/uid).
