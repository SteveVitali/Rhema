## Goal
Convert the editor's letter and the independent second read into a `findingsSidecar` and a
`rubricSidecar` that pass the real validators. Every severity, kind, origin and reconciliation the
converter assigns follows a declared rule and is labelled as an import-rule assignment. The
operator's accepted demo defaults hold everywhere, and no corpus text is ever paraphrased.

## In scope — deliverables
1. **Letter parser** `src/convert/letter.ts`: typed letter (verdict, the one thing, strengths,
   majors with Where/Problem/Why/Direction, minors, line notes, roadmap open questions,
   considered-and-rejected, scorecard), absorbing the R2 §1 letter variants. (REQ-CONV-7)
2. **Second-read parser** `src/convert/second-read.ts` (objections, strengths, verdict).
   Second-read strengths are not findings. (REQ-CONV-7)
3. **Reconciliation** `src/convert/reconcile.ts`: the override file is authoritative; the R2 §2.2
   overlap heuristic runs as a lint, and a heuristic/override disagreement is a build warning in
   diagnostics. Adds the reconciliation override kind to the 215 mechanism. (REQ-CONV-8)
4. **Findings** `src/convert/findings.ts` per the R2 §2.2 table: declared kind/severity/origin
   rules; `body` = Problem + Why + Direction verbatim, truncated only by the declared 4096 rule with
   "…"; `rubricDims`; `evidence.urls`; `suggestion` never emitted. (REQ-CONV-7)
5. **Rubric** `src/convert/rubric.ts`: the explicit eight-name map; a `cap` only where Basis
   states one; no aggregate computed or emitted. (REQ-CONV-9)
6. **Demo defaults** (REQ-CONV-16; `GD-DEMO-CONV.R7`) as one declared constant set this ticket
   owns: the one thing is `major` + `letterSection: one_thing`; no `blocking` anywhere in demo
   data; letter strengths are `note` rows with `letterSection: strength`; response rows that answer
   dossier notes (not a finding) are raw-table-only. The last default is consumed by 217.
7. **Import-rule labels** (REQ-CONV-14): extend `labels.json` with a per-field marker for every
   converter-assigned field — severity, kind, origin/reconciliation here, plus 215's `stance` and
   `accessedAt` — so 218 and 218a can carry "assigned by import rule" to every display. Generated label text
   uses S-10 roles and passes `lintCopy`.
8. **Raw-only registry** (REQ-CONV-13): the R2 §6 list as a declared constant (`RAW_ONLY` by
   artifact path pattern) that 218 consumes to serve those artifacts as raw markdown pages; plus a
   **verbatim invariant test**: every emitted `title`/`body` is a substring of the sanitized
   source, apart from the declared truncation.
9. **Validation**: every findings and rubric sidecar passes `parseSidecar`; any `failed` aborts.
   The R2 header negative controls for rubric names (`"Thesis & contribution"`,
   `"Voice & audience fit"`) and `letterSection: "minor"` return `failed`. (REQ-CONV-2, this half)
10. **Synthetic goldens** for findings and rubric, plus anchors for majors' `Where` text through
    the 215 ladder (section-heading fallback included). (REQ-CONV-12 amended, this part)
