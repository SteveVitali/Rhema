## Goal
`apps/egress-proxy`: the only route out of the sandbox subnet, the **usage meter of record**, the
run cap's enforcer, and the fetch log of record (REQ-SPEC-11). A TypeScript forward proxy (undici),
not Envoy, because per-run policy needs a DB lookup and body rewriting.

## Load
- Spec §12.7 end-to-end (per-run credential + orchestrator-issued allowlist; 403 `egress.denied`;
  usage-block metering incl. `server_tool_use` and cache writes; rate tables × 1.4; 402 at cap;
  cross-checks), §13.3 egress-proxy bullet (REQ-ARCH-31 amended), §12.8(d) (outbound-channel
  limits), §12.6 URL policy (server-tool body injection of `allowed_domains`/`blocked_domains`),
  §12.4 steps 4/9, ledger M10 (M15 auth spike resolved by design — direct Anthropic API, no SigV4).

## In scope — deliverables
1. **Credential gate:** present the Anthropic API key (read from Secret Manager) only for requests
   bearing a valid per-run proxy credential bound to that run's `proxy_allowlists` row (endpoints,
   models, URL policy, cap); strip any `Authorization`/`x-api-key` the sandbox sent; refuse other
   hosts or credential-less requests with 403 + `egress.denied` (credential *minting* is P0.08's
   provision step; this ticket validates and consumes). No SigV4/task-role signing path — inference
   is the direct Anthropic API.
2. **Metering:** read every response's `usage` block (incl. `server_tool_use`, cache read/write),
   tag `run_id/attempt/agent_id`, rate under the run's versioned rate table (§12.7 prices × the 1.4
   platform rate), write `usage_records{source:'proxy'}` — the rows of record.
3. **Cap enforcement:** when a run's Σ metered cost ≥ its cap, reject the next request with 402 (the
   engine sees `budget`); the residual overrun bound is one in-flight request (§12.4).
4. **URL policy + outbound-channel limits:** rewrite server-tool request bodies to enforce the run's
   URL policy; `web_fetch` query strings > 256 chars stripped/refused; per-run cap on distinct
   fetched registrable domains not present in the claim ledger or a search result; `search.performed`
   n-gram diff vs draft n-grams (≥12-word match → `suspicious_query`, pause signal) (REQ-SPEC-25's
   proxy half; §12.8(d)).
5. **Fetch log of record:** every request tagged and logged (never bodies) as `fetch_log` rows —
   the source for source cards and cited ⇒ fetched (REQ-DATA-16).
6. **Key handling:** provider keys only here, read at start and on SIGHUP (REQ-ARCH-30); BYO-key
   path stubbed (1.1).

## Out of scope (do NOT do here)

- The nightly provider reconciliation job (PRB.8) and the SDK cross-check wiring (P0.15).
- `fetcher` (arbitrary-egress service — PRB.2).

## Acceptance criteria
- [ ] Credential-less request from the sandbox → 403 + `egress.denied` row; valid credential +
      off-allowlist model/endpoint → 403. *(deterministic)*
- [ ] Fault-injection: inflated usage crossing the cap → 402 on the next request; Σ
      `usage_records{proxy}` for the run reflects every served response including the one that
      crossed (feeds the REQ-BILL-3 AC in P0.11). *(deterministic)*
- [ ] `server_tool_use` and cache-write tokens metered (fixture responses). *(deterministic)*
- [ ] A `web_fetch` body with a 300-char query string is refused/stripped; a search query matching
      12+ consecutive draft words emits `suspicious_query`. *(deterministic)*
- [ ] Sandbox `Authorization` headers are stripped (never forwarded). *(deterministic)*
- [ ] Every request produces a fetch-log row with `run_id/attempt/agent_id`, URL, status, decision.
      *(deterministic)*
