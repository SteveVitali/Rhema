## The problem (diagnosed live, P0.15i Stage B, 2026-09-09/10)

P0.15i made the fact-check's web research **real and proxy-logged** — a live `second_read=false` Review now
runs all 6 required phases (intake→craft→verification→discourse→argument→letter) and REACHES delivery with
`usage_records.searches` in the tens and ~190 `fetch_log kind='fetch'` result-URL rows. **But delivery still
throws `DeliveryValidationError("cited_not_fetched")`** (`packages/mirror/src/validation.ts`
`validateCitedFetched`, REQ-VIS-9 / §12.8(c)): the verification phase cites authoritative sources **from
training knowledge** (observed: snopes.com, scientificamerican.com, forbes.com, deadline.com, gale scholar,
etc.) that it never actually retrieved this session, so those URLs are absent from the run's fetch log. The
guard is all-or-nothing — a single un-retrieved cited URL fails the ENTIRE review.

**What has already been tried (do NOT redo, build ON it):** the editorial-review skill's Rule 5 was hardened
to "cite only tool-retrieved URLs; `web_fetch` any source before citing; mark unverifiable if you cannot pull
it" (commit `8d50f72`, in the vendored pin + regenerated port, `PROTOCOLS_VERSION` re-frozen). Live effect:
misses **18 → 14** and the model **began** using `web_fetch` (`usage.fetches` 0 → 2) — real movement, but
sonnet-5 did NOT converge to zero. `web_fetch` is enabled by default and works (GA, no beta header).

## What to build (Stage A — offline, choose the path deliberately)

The goal is a fact-check whose EVERY claim-ledger citation (`claim.url` + every `claim.sources[].url`) is in
the run's proxy fetch log. Two legitimate paths — the ticket owner picks after building the eval and, for
path B, getting the operator's spec ruling:

1. **The citation-discipline EVAL (build this first, either path).** A deterministic offline eval over
   real/recorded fact-check outputs that measures **citation-fetch compliance**: of the URLs a claim ledger
   cites, what fraction appear in the run's fetch log? Wire it so a run's compliance is reportable and
   regressions are caught. This is the measurement that turns "prompt guessing" into hill-climbing (§18
   spirit; reuse `@rhema/benchmark` scoring patterns where they fit).

2. **Path A — skill + model discipline (the rigorous fix; PREFERRED).** Drive compliance to 100% by: (a)
   strengthening the editorial-review verification instructions further (e.g. an explicit "before you write any
   claim-ledger row, `web_fetch` its source URL; if the fetch fails or you did not fetch it, the verdict is
   `unverifiable` and you cite nothing" — a per-claim fetch-then-cite loop), reconciled through the vendored
   pin + `check-upstream-diff.mjs --write` + `PROTOCOLS_VERSION` regen; and/or (b) running the **verification
   phase on a stronger model** (balanced=`claude-opus-5` or frontier=`claude-fable-5`) if the eval shows it
   follows the discipline where sonnet-5 does not. Iterate against the eval until compliance is 100% on the
   dev fixtures.

3. **Path B — a spec decision on `cited⇒fetched` semantics (ONLY with an explicit operator ruling).** IF the
   operator rules that `cited⇒fetched` means *"the citation is a real, retrievable source"* rather than *"the
   fact-check fetched it while verifying"*, implement a deterministic **harness citation-backfill**: before the
   delivery transaction validates, the harness `web_fetch`es (through the injector→proxy, so it is logged)
   every cited URL not already in the fetch log; a URL that fails to fetch still fails delivery (anti-fabrication
   preserved). **Record this as an ADR / spec-amendment** — it RELAXES the guard (it no longer proves the
   fact-check read the source while forming its verdict; the §12.8(c) verdict-source-check remains the grounding
   guard). Do NOT weaken `validateCitedFetched` itself (AC2 of P0.15i — the guard must still reject a genuinely
   un-fetchable citation).
