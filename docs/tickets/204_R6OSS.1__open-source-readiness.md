## In scope
1. **Docs amendment (ADR + records).** Amend `ADR-002` (protocols-committed-workspace-member) with a
   dated reversal note: the export-time swap (`packages/protocols` → `protocols-stub` rename) is
   **retired** — protocols ship public. Fix every doc that asserts the swap: `AGENTS.md` § Private
   packages (REQ-ARCH-37 amended-2026-09-01 line), `packages/protocols-stub` README/manifest (mark
   the stub as the now-dormant export shim — keep or delete honestly; the `public-safe` CI leg's
   meaning changes to "stub still compiles" → decide and record), `docs/ci.md`, any `docs/tickets`
   or ADR that cites the private-package invariant. REQ-ARCH-37's public-export clause needs the
   dated amendment.
2. **Full-history secret scan.** `gitleaks git --config .gitleaks.toml` over **all history**, not
   the tip — plus targeted greps for known incident classes: the scrubbed invite code, any
   `sk_live_`/`sk_test_`/`sk-ant`/`whsec_`/`re_`/`pk_` literals, DSNs (`postgres://`), the DWD
   mailbox credential material, WIF provider strings, webhook URLs, invite codes. Every hit gets a
   disposition row (real-leak → rotate+scrub decision surfaced to the operator; test-fixture →
   allowlist note; benign-id → recorded). Nothing is silently allowed — a real secret in history is
   an operator ruling (scrub+force-push vs rotate), never the worker's unilateral rewrite.
3. **Personal-data / internals audit.** Enumerate what's in committed history that a public reader
   sees: the operator's personal Gmail (`14stevevitali@gmail.com`) and `+r6lch1` alias, home paths
   (`/Users/stevenvitali`), internal IPs (`10.46.0.3`, `10.8.16.7` — the deleted `10.8.16.4`),
   GCP project id `rhema-507501`, Stripe object ids (`plink_`/`cs_live_`/`sub_`/`evt_`/`we_`),
   invite codes, workspace/user/run ULIDs, proxy VM names, WIF provider + SA emails, the `docs/build/`
   tree itself (LEDGER/runs/readouts contain all of the above + candid internal assessments).
   Produce a disposition table: **stays** (public-by-choice) / **needs-scrub** / **needs-ruling** —
   the operator's call on the big classes (personal email + build-memory tree visibility).
4. **OSS hygiene files.** `SECURITY.md` (reporting contact + supported-version posture),
   `CONTRIBUTING.md` (or a short pointer if you prefer minimal), issue templates if desired,
   confirm `LICENSE` (MIT) is the intended choice and `LICENSES.md` is current, README accuracy for
   a public first-reader, and a `.github/workflows` fork-safety check (no `pull_request_target`;
   secrets never exposed to fork PRs — verify each workflow's trigger).
5. **The export checklist + flip runbook.** `docs/ops/open-source-readiness.md`: the audit's
   disposition table, the scrub/rotate decisions outstanding, the exact flip steps (GitHub
   visibility toggle, branch-protection re-check, CI secrets posture on public repos — public repos
   get free Actions minutes but forks' PRs must not run workflows touching secrets), and what a
   post-flip verification looks like.
