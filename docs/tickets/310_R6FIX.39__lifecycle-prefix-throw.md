# 310_R6FIX.39 — lifecycle mutations die in `onMutate` on the `["bff","app"]` prefix match

**Status:** done (source fix + regression test; deployed-arm verify owed on the next deploy)
**Class:** run-time insert — deployed product defect (all row lifecycle actions silently broken on prod)
**Base:** `stevenvitali/r6fix-38-u3-stopgap-superseded` (stack)
**Branch:** `stevenvitali/r6fix-39-lifecycle-prefix`

## Defect

Nightly `T6`/`T7` have been red since the R7b `/app` deploy wave (~11-08/09): T6's deleted
row stayed present and T7 found no `project.purge` job — i.e. the delete itself never
landed. Prod evidence:

- The fixture rows (`JRN-DF6A31DC1BB9-T6DEL`/`-T7DEL`) exist untombstoned; no
  `POST /projects/:id/delete` reached the api AND no `POST /p/:slug/delete` reached the web
  host — zero delete POSTs from **any** user in 24h.
- Live reproduction on `73902381` ($0, flagged tenant): row renders, `⋯` opens,
  `[data-menu-action="delete"]` exists and is enabled; click AND keyboard Enter produce
  **zero non-GET requests** — only `GET /bff/app` + `GET /bff/app/inbox` refetches and the
  `toastFailed` toast ("That didn't go through — nothing changed").

## Root cause

`project-home.tsx`'s optimistic `patchTwinRows` iterates
`getQueriesData({ queryKey: ["bff", "app"] })` — a **prefix match** that also returns the
sibling `["bff","app","inbox"]` (shell badge, always cached) and `["bff","app","new"]` keys
whose payloads (`BffInboxTwin` `{items,badge,gateCards}`, the new-project twin) carry no
`rows`/`deletedRows`. `data.rows.map(...)` throws `TypeError` inside React Query's
`onMutate` → the mutation aborts **before `mutationFn`** → the `bffFetch` POST never issues,
`onError` toasts, `onSettled` invalidates the `["bff","app"]` prefix (the observed
`/bff/app` + `/bff/app/inbox` refetch pair). Every row lifecycle action — archive,
unarchive, duplicate, delete, restore — is dead on prod for every user whenever any sibling
key is cached. Introduced by `0ad737e3` (R7HOME.1, merged 11-05, in `73902381`); the leg's
DOM contracts never broke, so only the live POST absence showed it.

## Fix

`patchTwinRows` + the `onMutate` snapshot now iterate `homeTwinEntries()` — the same prefix
query filtered to home-shaped payloads (`Array.isArray(data.rows) &&
Array.isArray(data.deletedRows)`). Non-home siblings are skipped, never patched or snapshotted.
