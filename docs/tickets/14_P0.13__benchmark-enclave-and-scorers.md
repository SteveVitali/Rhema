## Goal
The §18 program's data layer: the access-logged corpus enclave, the gold-annotation schema and
intake tooling, contamination-control records, and the deterministic scorer set — everything the
wave runner (P0.14) scores with. Runs beside `evals/`, reusing its fixture/scorer framework
(REQ-EVAL-20).

## Load
- Spec §18.1 (corpus, contamination, enclave, gold set, power), §18.3 REQ-EVAL-11/12/13/14 (the
  metric definitions this ticket's scorers compute deterministically), §13.5 (evals framework it
  extends), REQ-EVAL-1…5, REQ-EVAL-20.
- Note: corpus **content** is commissioned by the operator (human row in 00_MANIFEST.md); this
  ticket builds the machinery and exercises it on the frozen dev set (the three real projects).

## In scope — deliverables
1. **Enclave:** private, access-logged store (S3 + rows) for corpus drafts and gold annotations;
   logged reads; never referenced from fixtures/demos/marketing paths; per-draft evidence records
   for the REQ-EVAL-2 contamination controls (creation date vs cutoffs, attestation, near-duplicate
   search result, canary id, per-wave memorization-probe outcome with the pre-registered exclusion
   rule); ≥20%/yr rotation bookkeeping (REQ-EVAL-3).
2. **Gold-set tooling:** annotation intake in the §5.7 Finding schema + `material` flag; two-editor
   independence + senior adjudication workflow records; per-draft IAA computation with the
   agreement floor (REQ-EVAL-4).
3. **Deterministic scorers:** anchoring/specificity (the §5.7 anchor ladder), severity-calibration
   kappa, voice-preservation via `packages/measure` bands + the claim-inventory meaning diff
   (REQ-EVAL-12), second-read marginal contribution over human-matched data (REQ-EVAL-13),
   cost/latency join from proxy metering (REQ-EVAL-14), recall/FP computation over adjudicated
   match records (the matching itself is human — P0.14's tooling), style-perturbed-control and
   finding-diversity metrics (C-e, C-f).
4. **Power machinery:** paired per-draft analysis implementation; variance estimation from the pilot
   wave; n-fixing rule (≥80% power for 10 points, floor 24) (REQ-EVAL-5).
5. **`evals/` integration:** shared fixture format; the three real projects as the frozen dev set,
   flagged so dev-set numbers can never enter a headline table (REQ-EVAL-1).

## Out of scope (do NOT do here)
- Arm runners, normalization/extraction, the human matching/adjudication UI, wave orchestration,
  pre-registration hashing, reports — P0.14.
- Corpus commissioning, editor contracting, provider written verification — human rows.
- LLM-judge machinery (secondary metrics; P0.14 with the C-a…C-g hardening).

## Acceptance criteria
- [ ] Enclave access test: every read of a corpus draft leaves a log row; no public/fixture path can
      resolve enclave content (REQ-EVAL-3). *(deterministic)*
- [ ] A draft missing any REQ-EVAL-2 evidence field cannot be admitted to a wave manifest.
      *(deterministic)*
- [ ] IAA computation verified against a hand-computed fixture; below-floor drafts flagged for
      re-adjudication/drop (REQ-EVAL-4). *(deterministic)*
- [ ] Scorers reproduce hand-computed values on a synthetic-flaw fixture set (labeled
      scorer-development-only, never publishable — REQ-EVAL-1). *(deterministic)*
- [ ] Voice scorer: a "laundered" (surface-polished, substance-unchanged) fixture does not move the
      meaning diff; every dropped Tier-1 claim traces or violates (REQ-EVAL-12; C-e).
      *(deterministic)*
- [ ] Dev-set flag: a wave report render with a dev-set draft in a headline table fails.
      *(deterministic)*
