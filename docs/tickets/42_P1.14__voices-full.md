## In scope — Stage A (code + tests, PR-able)

1. **The `/app/voices` destination (REQ-PERSONA-1).** Three fixed groups — *Your voices*
   (editable, buildable), *House styles* (read-only, forkable; the group + schema render now,
   platform content is 1.x per REQ-PERSONA-19's deferral), *Shared with you* (only when non-empty).
   Cards: name + byline, status pill, sample count + source summary, projects using it, last-built
   — never credits. Empty state uses the §9.1 copy direction ("Your writing has a voice…" — never
   "writes like you"; the banned-strings lint covers it).
2. **Full Profile builds (REQ-PERSONA-5/6/8/9/10/11/13).** The creation sheet's Full Profile radio
   goes live (locked under Free with "Available on Writer" — the entitlement check is P1.16's;
   the lock UI + the gating flag land here). Requirements enforced: name required, ≥1 description
   or sample to build, hold-out math needs ≥4 samples (two at ≥10). The `profile_voice{tier:full}`
   run drives the existing manifest end-to-end: corpus census → `approve_sample` gate → close
   reading → voice → substance → calibration → package; snapshot rows into `persona_profiles`;
   build note into `persona_build_notes`; `editMode:'none'` on every derived artifact.
3. **Approve sample card content (REQ-PERSONA-12).** On P1.09's card chrome: corpus census counts,
   exclusions with reasons, the hold-out line in plain words ("one of your pieces is held back to
   test the profile — you won't see which until after calibration"), estimate + cap, the three
   knobs (sample cap; calibration on/off carrying the skill's warning that off leaves the profile
   untested; model tier). Wait-default per §6.4.
4. **Fetcher-only URL path + leak audit (REQ-PERSONA-11, §12.6).** Publication-link/URL samples
   for a persona fetch through the persona builder's client-side fetcher tool under the path-level
   URL policy — never a credentialed/session path (never-cookies is P1.15's AC-I-B; this ticket
   must not regress it). The hold-out leak audit: any `HOLDOUT-*` read outside the calibrator's
   input scope voids calibration → `calibrationStatus:'untested'` + a flag on the build note —
   assert the audit fires and voids.
5. **The eight-state pill, live (REQ-PERSONA-14/15/16).** Remove the `BETA_VOICE_STATES` filter:
   `aged` (>180 d or corpus +25% vs build) and `badly_off` (calibration `tested-badly-off` —
   threshold per the §16.3 #10 resolution above) join the reachable set. One `deriveVoiceStatus`
   call feeds the library card, the detail header, the project chip, and the run sheet's voice
   row — the pill is one function, not four renderers. The popover/diff-of-inputs panel lists the
   four facts (seed hash vs build, sample-set hash vs build, corpus size vs build, calibration
   status) with concrete deltas in plain words and exactly one verb: **Update voice**.
6. **Update voice → scope routing (REQ-SPEC-27).** One verb; the router maps state+facts to the
   cheapest sufficient scope: `synth` (seed-only change → re-render derived prose, no re-reading),
   `delta` (sample-set change under threshold → `refresh_voice{scope:'delta'}`), `calibrate`
   (untested profile → `calibrate_voice`), `full` rebuild, `full_from_quick`. The run sheet shows
   the chosen scope + estimate before consent. Corpus notes persist per content hash so a delta
   costs <30% of a full build (REQ-PERSONA-16 — the notes are artifacts; assert reuse).
7. **The detail page (REQ-PERSONA-17/18; AC-P-C).** Five tabs:
   - **Overview** — hub paragraph, status card (the pill + panel), calibration summary phrased as
     capability not verdict, projects using it, the decisions checklist.
   - **Description** — the seed editor (plain Markdown + Byline/Mode/Registers fields; the
     Notes-from-last-build card; autosave → `seed_hash` recompute → pill updates live). The
     *only* correction path: "Correct this in your description" deep-links and inserts a
     blockquote of the wrong statement → a `profile_corrections` row (REQ-VIS-8/REQ-PERSONA-7).
   - **Samples** — mounts P1.15's samples manager (the tab chrome + data wiring land here against
     the PRB.10 item list; the full manager is P1.15).
   - **Profile** — fixed section order: Calibration report first (prediction vs real opening
     side-by-side, the within-one-band table, corrections applied, blind-check reasons; untested →
     empty state with a priced *Test this voice* → `calibrate_voice`), Exemplars (≤12 quotes,
     ≤40 words), Positions & open tensions, Continuity, Structure (collapsed), Voice measures
     (from `packages/measure` — ranges beside means, rations + anti-signature; Method stays
     hidden), Lexicon. Every derived section has `editMode:none` — assert a write attempt → 405.
   - **Runs** — platform run list filtered to the voice's workflow keys; per-run credits,
     duration, phase breakdown, samples used, what changed; the per-voice spend total; tokens only
     under the Advanced disclosure.
8. **Profile corrections lifecycle.** "Correct this…" → `profile_corrections` row (text, source,
   target); the next refresh consumes unconsumed corrections (marks `consumedByProfileId`) and
   the build note lists them; consumed corrections never re-apply (REQ-PERSONA-7's lifecycle).
9. **Project adopt/fork — the soft lock (REQ-DATA-30/31/32).** New projects default No voice /
   ad-hoc; voice freely changeable before v1; after v1 a direct change is **rejected by the API**
   (assert 409/422 on `PATCH /projects/:id`) with the two hatches offered: **Fork under another
   voice** (new project at `outlined` with the copied outline + the new voice) or **Adopt the
   refreshed profile** (updates `persona_profile_snapshot_id` — the project keeps its voice,
   gets the newer snapshot). Optional charter reseed runs `reseed_charter`, shows the diff before
   commit, never touches guidance lines, logs the decision (REQ-WF-11's persona half).
10. **Composites + registers (schema surfaces; REQ-PERSONA-22/25/26).** `persona_members` renders:
    a composite card shows "Composed from A, B" + member pills; imported composites are read-only
    and require a **Register** pick at run launch for multi-register voices — the selector feeds
    the skills' `register` input and the hook's `compositeVoiceMemberFiles` mount. (The composite
    *builder* is REQ-PERSONA-20 — 1.x.)
11. **`packages/measure` — deterministic prose metrics.** Fill the skeleton: the sentence/lexical
    statistics the calibration comparison table and Voice-measures section render (sentence-length
    distribution, punctuation rates incl. em-dash/1k, type-token ration, the rations the profile
    schema names). Pure TS, no model calls, deterministic; consumed by the calibration table here
    and the Assistant's `measure` tool (P1.11). Output schema lives in `packages/contracts`.
12. **Hold-out reveal (REQ-INGEST-13's display half).** Hold-out identity stays hidden until
    calibration completes — then the item is badged ★ held out and linked in the samples list.
    Assert: pre-calibration, no API response or rendered surface names the hold-out.
