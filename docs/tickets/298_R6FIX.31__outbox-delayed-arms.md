# 298_R6FIX.31 — durable outbox for the delayed arms (BL-115)

**Status:** done (Stage A; PR opened, unmerged — OPERATOR)
**Class:** run-time insert — BL-115 delayed-arm transactional-integrity repair
**Base:** `main` @ `7bd38f47`
**Branch:** `stevevitali/r6fix-31-outbox`

## Defect

The three delayed arms did mark-then-send across two datasources: the marker committed on the app
DB (`user.deletion_requested_at`, `projects.deleted_at`, the `account_exports` 'building' row) while
the pg-boss job row landed on the system DSN — a crash between them left an armed marker with no
job (or, pre-RH-17, a silently dropped send). The hourly watchdogs repaired it eventually; the BL
row named the honest same-seam fix as the outbox pattern. **Operator ruling 2026-11-16: outbox
pattern.**

## Implementation

- Migration `0064_outbox.sql` + `packages/db/src/schema/outbox.ts`: a system-scoped `outbox` table
  (workspace_id key for ops visibility, NOT an RLS table — the `pause_signals` posture);
  `claim lease (claimed_at, 60 s) + bounded attempts (25) + sent_at` machinery; the drain's pending
  scan rides a partial index on unsent rows.
- Grant class per the 0045 census: `grant insert on outbox to rhema_app` — the user-serving role
  writes the intent inside its tenant tx (the `slo_samples` "i" class); the drain's
  select/claim/mark all ride the system pool. A forged intent can at worst enqueue a job whose
  handler re-validates the durable marker and no-ops — the marker, not the row, is the state.
- `apps/api/src/outbox.ts` (`insertOutbox`): the three routes now write marker + intent in ONE
  `txRunner` tx — `settings-routes.ts` `account.hard-delete` (first-request clock preserved;
  `startAfterMs` to the 14-day grace end; singleton `account.hard-delete:<userId>`),
  `project-routes.ts` `project.purge` (outbox only after the tombstone update returns a row;
  +30d `PROJECT_PURGE_AFTER_MS`; singleton `project.purge:<projectId>`; the `.catch(() => undefined)`
  swallow is gone — there is no request-time send to swallow), `account-export-routes.ts`
  `account.export` (building row + intent atomically; singleton `account.export:<exportId>`).
- `apps/worker/src/outbox-drain.ts`: `drainOutbox` claims pending rows `for update skip locked`
  on the system exec, sends through the injected `Queue` with `payload` + `send_options` verbatim
  (`toPgBossSendOptions` keeps `startAfterMs`→`startAfter` and `singletonKey`), marks `sent_at`
  only after the send lands, records bounded `last_error` on failure. Registered as
  `outbox.drain` (WORKER_QUEUES + createQueue + `boss.work` + `boss.schedule("*/1 * * * *")`).
- Watchdogs retained as the belt (drained-but-never-sent rows re-arm on the lease; the hourly
  sweeps still catch exotic loss); they are no longer the primary mechanism.
- Census pins: `WS_EXEMPTIONS` + `USER_ROLE_GRANTS["outbox"]="i"` in `rls-catalog.test.ts`.
