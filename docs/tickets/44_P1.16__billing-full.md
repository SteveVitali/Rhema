## In scope — Stage A (code + tests, $0)
1. **`pricing.json` — the one versioned pricing artifact** (REQ-GROWTH-4): plan ladder rows, annual
   prices (15% saving), top-up packs ($10→1,000 · $50→5,250 · $200→22,000), the §15.2 cost cards
   and the "What it covers" lines — all generated, never hand-edited. Lives where both `apps/api`
   (rate publication) and `apps/web` (pricing page, plan card) can consume it (`packages/contracts`
   beside the rate tables is the natural home); a contract test pins its figures against the
   `RateTable`/`PLATFORM_RATE` constants.
2. **Plan ladder via Stripe.** Subscriptions for Writer/Studio/Studio Max (monthly + annual −15%)
   through Stripe Billing; Checkout for subscribe + top-ups; Customer Portal for plan changes,
   payment methods, invoices; Stripe Tax on; **Team listed with its price and a waitlist CTA**
   until roles ship (REQ-GROWTH-7). Subscribe flow per §14.6: Checkout → `checkout.session.completed`
   + `invoice.paid` → `grant(included, expires cycle_end + 1 month)` → return to where the user
   started, **re-opening the estimate sheet with the same configuration** if that is where they
   came from (REQ-BILL-14). Downgrade applies at cycle end with a 7-day warning when the balance
   exceeds the new 2× cap; cancel keeps access to cycle end and top-ups keep their expiry
   (chat-only spendable on Free).
3. **The trial entitlement** (REQ-SPEC-8; closes D-P0.11-2): `TrialEntitlement {kind:'review',
   wordCap:6000, rigor:'standard', modelTier:'base'}` + the `trial_pocket` bucket (150 cr, expires
   day 14). The state machine `trial_pending → trial_active|trial_denied → trial_used → free`
   drives account rows; an entitlement Review holds and debits against the entitlement
   (`Run.entitlementId`), never credits; the sheet, run card and run report render **Included** —
   no dollars, no cap arithmetic, no consent second click (§5.6 item 9). Balanced/Frontier and Full
   board render locked-with-price; >6,000-word drafts offer "review the first 6,000 words, or
   upgrade"; the first-section draft preview (≈60 cr) and chat/figures/Quick Voice spend from the
   pocket; on subscribe inside the window an unused entitlement converts to an **800-credit `promo`
   grant** and an unspent pocket converts likewise.
4. **Unlock + abuse controls** (REQ-GROWTH-10, REQ-GROWTH-15 amended): verification deferred to
   spend — Google users verified by OAuth, magic-link users by the link click; the unlock runs at
   the first cost-bearing action through a disposable-domain check, device/IP fingerprint and ASN
   scoring, and a one-trial-per-fingerprint rule; phone/OTP challenge only above the risk
   threshold. Trial runs are Base-only, 1 concurrent, ≤6,000 words, on the cheapest research
   routing; a **global daily trial-spend ceiling** pauses new unlocks automatically when crossed;
   a workspace-level **kill switch voids trial entitlements and pockets within 60 s** (admin CLI
   extension in `admin.ts`/`admin-cli.ts`); the one-line eligibility rule is published on the
   pricing page (P1.17 renders it).
5. **Rollover / expiry / top-ups / auto-reload** (REQ-BILL-15's order already in P0.11 — wire the
   surfaces): included balance ≤ 2× monthly, excess expires at reset with a 7-day warning; top-up
   packs grant `topup` at +12 months, drained after included; first-month top-ups capped at $100
   per new account; >$200/day requires 3DS. **Auto-reload is opt-in only** — "when my spendable
   balance falls below [500], buy the [$10] pack, up to [$50] per month" — the single
   charge-without-a-click path, bounded by the user-typed cap (REQ-BILL-17).
6. **The four-level usage dashboard** (§14.5; REQ-BILL-8…12): **0** balance chip (spendable; held
   on hover; days to reset — always visible); **1** `/app/usage` (period bars included/top-up/held,
   totals in credits + $, by-project table, by-workflow donut, alerts, CSV); **2**
   `/p/:project/usage` (runs list cost/duration/status, cost by round, cost by seat incl. the
   seat→subagent split, per-project cap); **3–4** the run-report levels — the read models
   (`AccountUsage`, `ProjectUsage`, `RunSummary`, `RunReport`, `RunAdvanced`) are delivered here
   as separate types while their surfaces land on P1.05's run report: `AccountUsage`/`ProjectUsage`
   have **no `tokens` field**, `RunReport.advanced` loads only on disclosure open, and no level
   exposes prompts, private memory, transcripts or source-note bodies. **Flags** are computed
   server-side with templated sentences when a cause is ≥20% of cost or actual deviates ≥25% from
   estimate (`fact_check_dominated`, `long_draft`, `discourse_map`, `second_read_model`,
   `over_estimate`, `under_estimate`, `retries` — REQ-BILL-9); levels 1–2 export CSV
   (REQ-BILL-11); levels 0–1 and the run-report header read models are read-only-JSON-safe for the
   phone layout (REQ-BILL-12 — the layout itself is P1.19). The "what drove it" line and the FAQ
   quote the named constants — `cost_per_verified_claim.review[tier]` ≈ 24/53/108 vs
   `…fact_check[tier]` ≈ 11/26/51 — never interchangeably.
7. **REQ-BILL-7 estimator re-fit**: a weekly worker job re-fits per workflow × rigor × model tier;
   the 1.5× cap multiplier holds until trailing-30-day p95 actual/estimate < 1.3, may then drop to
   1.35, never below 1.25; the variance reserve is reported internally. Folds the PRB.14/PRB.17
   measured-cost work (`estimatorsAreProvisional()` and friends) rather than re-deriving it.
8. **Every §14.6 failure state, an integration test each** (REQ-BILL-16): card declined (stay on
   Checkout); renewal failed (Smart Retries 7 days → banner → runs continue on remaining balance →
   Free after 14 days, data untouched); chargeback (suspend + clawback per REQ-SPEC-24.7 — PRB.08's
   path, re-verified at plan level); run failed/refused (refund, partials kept, provider text
   verbatim); **estimate service down → runs do not start**; provider outage mid-run (retry from
   files; >3 retries → fail + refund); rate-table change while parked (re-price at resume, spend
   gate for the delta — REQ-SPEC-24.3's resume surface in full, incl. a parked run crossing a
   downgrade); parked >30 days (auto-cancel, release, partials kept); reconciliation drift (silent
   user-favourable refund); webhook lag (Checkout success polls ≤30 s then emails).
9. **`/pricing/rates` full publication** (REQ-BILL-19): current + previous rate tables with
   effective dates and the 1.4× platform rate; every run report links its frozen
   `rate_table_version`.
10. **Tier gates + surfaces** (REQ-PERSONA-5, REQ-DATA-42): Free/trial = one voice, Quick Voice
    only, Base (P1.14 consumes the gate flags); plan feature gates (concurrency, model tiers,
    sharing, export formats) enforced server-side from the ladder, not scattered in UI; runs are
    charged to the project's workspace account with per-run and monthly caps applied and consent
    bound to the invoker.
11. **Upgrade prompts, contextual only** (REQ-GROWTH-14): the estimate sheet on the second review;
    the end-of-review card ("Full board adds near-final line depth and a second reader from a
    different model family" — **no "a third more findings" number** until measured in-product); the
    day-12 email + card ("Your Writer features end in 2 days. Your projects stay."); locked
    controls in the sheet are the only place a plan name appears in the IDE. Never interstitials on
    project open, a persistent Upgrade nav button, or export nags.
12. Deterministic verification: `turbo build lint typecheck` + `pnpm test` green; every failure
    state above has its integration test; the vocabulary lint stays clean (credits/cap/top-up/plan;
    "overage", "on-demand", "ACU", "unlimited" and raw tokens outside Advanced are banned —
    REQ-BILL-18).
