## Goal

The **Draft** verb works end-to-end: `draft-from-outline` is vendored at the upstream pin and
ported through the sanctioned-diff machinery, the `draft` manifest encodes the §12.2 row verbatim
(eight phases incl. the declared `grounding → plan` back-edge), the Approve-plan card edits the real
`02-structure-plan` (P1.09's fields against a live artifact), the Page streams one section at a
time under a per-section budget bar while the writer lock holds, the fidelity audit runs
input-scoped, and the drafting note delivers into correspondence. The manifest validates
estimates ≤ caps against the §12.2 constants, and the re-plan cap escalates to an Approval on the
third grounding failure (REQ-WF-5).

5. **Approve plan, live.** The `approve_plan` gate fires after the plan phase with `gateArtifact`

   + `Guidance{source:'gate_edit'}` rows; **Keep planning** re-runs the plan step once per
   REQ-GATE-6's bounded re-plan (≤1, counted on `runs.replans`). The card's do-nothing line is the
   24 h → `autonomize` default (REQ-GATE-4's writer-lock Cancel-release line rides the same card).
6. **Back-edge + escalation (REQ-WF-5).** Grounding verification that fails a claim's predicate
   routes the `grounding → plan` back-edge (the plan re-runs with the failure as input — the
   re-plan gets the grounding output as context, not a blind retry); the third failure opens a
   `refusal`-kind Approval on the run — body: "Sources for claim X could not be verified" with
   actions proceed-with-`[unverified]` (approve + guidance) / cut the claim (edit) / stop —
   resolved through `resolveGate`, never a silent continue. `[unverified]` marks in the ledger
   persist into the draft's source apparatus (REQ-WF-5's badge path feeds P1.02's marks).
7. **Streaming writing phase (REQ-WF-4).** The draft phase emits `section.drafted` events per
   section; the Page (P1.02 surface) shows the single in-flight section streaming under a
   per-section budget bar (`remaining = cap − metered`, filled from `cap.credited`/`spend.tick`
   events) — never parallel sections, never a drafting subagent. Assert the constraint structurally:
   the draft phase's `agent` carries no `allowsSubagents` drafting slot and the hook rejects Agent
   calls during that step (§12.6 "the Drafter has no drafting subagent"). Sections arrive in plan
   order; a failed section → the phase's completion predicate → guidance path.
8. **Drafting note.** The delivery phase packages `vN-drafting-note` (voice choice + choices made +
   caveats + `[unverified]` claims + open questions + not-covered + numbers) and publishes it to
   correspondence (`kind:'drafting_note'`); the P1.04 correspondence surface renders its sections as
   cards and it is the first thing shown when a Draft run ends (§8.2 row 4). Assert the artifact
   lands + the correspondence row exists.
9. **Trial first-section preview hook.** The draft run accepts a `preview:{sections:1}`-style input
   bound to the run sheet's "Draft the first section (preview, ≈60 cr)" affordance (§7.6's
   next-step card; REQ-CHAT-30's preview) — the estimate pre-pass prices it, the Approve-plan gate
   is pre-resolved `by:'trial'` per §14.3's rule. P1.16 owns the entitlement; this ticket owns the
   run-input + pricing + gate-skip path.
10. **Registers.** Update `manifest-index.ts`, the workflow registry, the estimator's `WORKFLOW_LABELS`,
    `pnpm-workspace.yaml`/package exports as needed; §12.2's Draft row is now real in
    `manifest-checks` coverage (no longer only in `workflow-map.test.ts`).

## Cross-cutting invariants — re-check before opening the PR

- Drafting is never fanned out — no drafting subagent, no parallel sections, the hook enforces it.
- Seat boundaries (§12.6): the Drafter never reads `agents/editor/**` or persona hold-outs; the
  audit is a separate input-scoped subagent (≤3) reading only what its allowlist names.
- Guidance carries user edits; the Drafter keeps authorship (REQ-SPEC-14; §6.2 in-run edits).
- The writer lock: the Page's run-projected draft is read-only until the run ends; Cancel releases
  it (PRB.07 invariant — re-asserted, not weakened).
- Canonical vocabulary — Draft verb = "Draft"; card name "Approve plan"; tiers Base/Balanced/Frontier.
- See 00_MANIFEST.md § Cross-cutting invariants.
