## Goal

`outline-from-research` is ported at the upstream pin, the `outline` manifest encodes the §12.2
row (harvest → classify → spine → gaps, `approve_outline` gateAfter the gaps phase — a wait gate,
never auto-proceeds), the promotion flow turns an Assistant thread into a run whose product is a
versioned `outline` artifact with the provenance header and `[unverified]` bullets, and the
spine-and-sections structured editor — the same component as the Approve-plan card's fields,
unlocked — edits the outline with autosave/versioning and keeps the Draft estimate live. Approving
moves the project to `outlined` and offers the next step; on a project with a draft, the new
outline is vN+1 and offers `/draft @section`.

## In scope — Stage A (code + tests, PR-able)

1. **Vendor + port `outline-from-research`.** Same procedure as P1.10 deliverable 1:
   upstream-pin verbatim, sanctioned transforms declared (tools/model templating,
   `references/`/`agents/`/`evals/` → `@rhema/*`, NAMESPACE.md, `phase-result.json`), port
   regenerated, CI drift job green.
2. **`manifests/outline.ts`** — harvest (package — assembles the thread's source notes +
   research index), classify (judge — groups claims/sources), spine (generate — the
   provenance-carrying outline), gaps (judge — alternatives considered + gaps-only-the-author
   list; `gateAfter:'approve_outline'`, `gateArtifact` the outline artifact, spine bound 5–12).
   Estimator `ESTIMATORS.outline = 20 + 0.004·thread_tokens + 6·urls_refetched`; `checkSatisfiable`
   green. Register the workflow key + label.
3. **Promotion flow.** The three triggers all build the same run sheet: workflow **Outline**,
   scope thread-or-turn, levers thesis (prefilled from the thread brief when one exists) / venue /
   target length / protocol / voice; the estimate pre-pass prices thread_tokens + urls_refetched.
   The run re-fetches each thread URL through the fetcher (URL policy + proxy cap from the seat);
   a failed re-fetch yields a `[unverified]` bullet citing the failed URL — the claim is never
   silently dropped. No new searches unless the author asks (assert: the fetch phase's query set
   is exactly the thread's URL set).
4. **The outline artifact.** `agents/author/outline/<slug>.md` with the provenance header
   (sources, fetched-at, per-claim provenance inline), spine, sections with claim bullets,
   alternatives considered, gaps, sources — plus a parsed sidecar if the editor needs one (the
   claim rows' provenance markers must survive every edit — REQ-DATA-23's preservation rule).
5. **Approve outline (REQ-CHAT-15).** Wait-default, never auto-proceeds, presence timer never
   applies. Card shows the structured outline + gaps + unverified count + the next estimate
   ("Draft on Balanced ≈ 940 credits" — priced from `ESTIMATORS.draft`); actions Approve /
   Edit in outline editor / Back to chat with notes (edits ride `GateEdit` → overlay + Guidance).
6. **Approval consequences (REQ-CHAT-16/17).** On approve: write the outline artifact, migrate
   the thread's source notes to `agents/author/research/` (copy, not move — chat notes stay in
   the assistant namespace), set `projects.status='outlined'`, emit the next-step card → Draft v1.
   On a project whose latest draft exists: the outline is vN+1, the draft is untouched, and the
   next-step card offers `/draft @section` (the Draft run accepts a section scope — P1.10's run
   input). Assert the transition + the note migration + the version number.
7. **The structured outline editor (web-only; REQ-CHAT-18).** The spine-and-sections component
   from P1.09, unlocked: section rows drag to reorder and carry target words / function / entry /
   exit fields; claim rows drag between sections and keep their provenance marker + `[unverified]`
   badge (badges cannot be edited away — only resolved by a successful re-fetch); every edit
   autosaves — v1 edits in place, post-approval edits create `outline` v2+ (version bump +
   timeline event + the drafting note records which version a draft used). The Draft estimate
   line on the page updates live as target words change (`ESTIMATORS.draft` over the edited
   fields). Delete is disallowed once a draft cites the outline (REQ-DATA-23 — assert the API
   rejects). Phone-width: the outline renders read-only; approval happens on the card.
8. **Gaps → elicit.** Each "gap only the author can fill" row carries an **Answer** affordance
   that opens an `elicit` question (P1.11's tool); the answer lands as an authored claim row
   (provenance `user_typed`) — wiring the Interview-me cheap path §6.2 prescribes.
9. **Run-sheet + registry plumbing.** The Outline run appears in the verb catalogue with its
   levers; `WORKFLOW_LABELS`/estimator labels updated; the `/outline` command registered
   (§7.2 surface — the command palette is P1.01's, the command entry here).

## Cross-cutting invariants — re-check before opening the PR

- `approve_outline` never auto-proceeds and never shows the presence timer (REQ-CHAT-15; wait-default).
- Provenance survives editing — a claim row's source marker and `[unverified]` badge are data, not
  text; the editor cannot strip them (REQ-DATA-23).
- Two-conduit rule preserved: the outline artifact is the sanctioned conduit; the run reads the
  assistant namespace at harvest time but the *product* lives in `agents/author/` (REQ-SPEC-15).
- Canonical vocabulary; the harness never named; "tokens" only under Advanced.
- See 00_MANIFEST.md § Cross-cutting invariants.
