# 308_R6FIX.37 — Content reads bind the workspace-scoped store (outline/chat/project)

**Status:** done (Stage A; live verify owed on the next deploy — the defect 500s on prod `73902381`)
**Class:** run-time insert — verification-sweep finding (deployed prod defect, D-R6OPS.5-2 evidence)
**Base:** `main`

## Defect

**F-R6FIX.37-1** — production logs under `73902381` showed real user-facing 500s:
`unhandled_route_error` on `GET /projects/:id/outline`, stack
`GcsContentStore.get → readTextFile → outline-routes.ts`. Root cause: the api's shared
`contentStore` dep is the **unbound write-side** `GcsContentStore` (server.ts wires
`createGcsContentStore({ bucketName })` without a workspace — its `get` throws by design;
read-capable stores must be workspace-bound). The outline, chat, and project routes bound
`contentStore` for reads, so any read that resolved an `artifact_versions` row threw instead
of serving bytes:

- `GET /projects/:id/outline` (md + sidecar reads) — the observed 500s.
- `GET /projects/:id/chat` + pins/remembers/sources/notes reads — every `readTextFile` /
  `turnReplies` / `turnUserTexts` call once a session artifact row exists.
- `POST /projects` genre apparatus probe — `readStructureRepertoire` silently degraded to
  null behind `.catch` (REQ-GENRE-4's Academic default could never fire).

The export/dossier/editor/figure/triage/version routes already resolve reads through
`contentStoreFor(workspaceId)`; these three were the outliers.

## Implementation

- `OutlineApiDeps`, `ChatApiDeps`, `ProjectApiDeps` gain
  `contentStoreFor?(workspaceId)`; each read seam resolves
  `(deps.contentStoreFor ? await deps.contentStoreFor(workspaceId) : deps.contentStore)` —
  identical to the export/dossier `storeFor` idiom.
- `readTextFile` (outline + chat), `promotionFacts`, `readIndex`, `turnReplies`,
  `turnUserTexts`, and `readStructureRepertoire` take the principal's `workspaceId`
  (already verified against the project by `gate`/`loadProject` — no new trust surface).
- `index.ts` forwards `deps.contentStoreFor` into `createOutlineRoutes`,
  `createChatRoutes`, and `createProjectRoutes`.
- Writes keep `contentStore.put(workspaceId, …)` — `put` is workspace-parameterized and
  correct on the unbound store.
