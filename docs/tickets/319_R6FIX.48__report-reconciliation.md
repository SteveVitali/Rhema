## Defect — harness, not product (initial read corrected)

R6's report-vs-meter arm treats only a rendered `data-refund` line as a valid explanation
when the report's charged figure (`data-estimate-line`, Σ `debit` − Σ `refund`) comes out
below the run card's committed meter. That misses the designed RPT.1 mechanism: the report
renders `data-metered-line` ("{metered} cr metered · {charged} cr charged") plus one
`data-difference` row per reasoned reconciliation — `cap` / `absorbed` / `entitlement` /
`committed` / `refund` — and `cross_check` as a display-only estimate cross-check
(`packages/findings-core/src/run-report.ts` `reportDifferences`).

Verified live on the failing run's report twin (`/bff/p/:slug/r/:runId`):
`spentCredits 360` (charged = 42+30+143+53+92 debits), `meteredCredits 523` (Σ proxy usage
rows = the card's meter), `differences: [{absorbed: 163}, {cross_check: 355}]` — the full
gap is disclosed. `credit_ledger.kind='adjustment'` rows are all `reason='absorbed'`:
committed-mode (debitMode flip-1 parked) metered overrun the platform absorbs into the
variance reserve — never a user charge. Standing mechanism: N6 71, N11 661, academic 342,
op-ed 856, memo 213 the same window; R6 runs 1–2 needed none so the arm never exercised
this path until this run.

## Fix — `packages/journeys/src/steps.ts` R6 leg

Replace the refund-line-only check with the RPT.1 reconciliation contract:

- `reportSpent > finalSpent` still fails ("a charge no meter recorded").
- `reportSpent < finalSpent` now requires the gap-explaining `data-difference` rows
  (keys `cap`/`absorbed`/`entitlement`/`committed`/`refund`) whose rendered "{n} cr"
  figures sum to the gap **exactly** — matching `reportDifferences`' construction, which
  always fully attributes `metered − charged`. `cross_check` is excluded by key.
- Refunded runs are covered by the same check: refund rows ride `data-difference`, so the
  old `data-refund` special-case is subsumed.
- The existing after-checks stay: every difference row must render reasoned text (never a
  bare key), and the `data-metered-line` charged figure must equal `data-estimate-line`'s
  spent figure.
