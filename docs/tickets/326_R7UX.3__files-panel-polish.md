## Goal

BL-94 (R5 B10, P2): the Files panel is a dense 11–12 px wall — a lock glyph on every
draft, `'System · review run · verification'` provenance lines on every row, no file-type
icons, no hover affordance. Rebalance: readable type scale via the `ui-*` tokens, the lock
glyph only where a lock is actually meaningful (read-only/demo rows — not every draft),
provenance collapsed to a single subtle line or tooltip, file-type icons, and a hover
state that signals clickability. Same rows, same navigation — presentation only.

## Spec §§ / anchors

- The files tree under the IDE panel (`apps/web/src/spa/ide/` `chrome*.tsx` and the
  `files-labels.ts` vocabulary). Read-only/demo locking lives on the same rows —
  `demo`/`readOnly` flags — gate the glyph on those, not on "is a draft".
- ReadOnlyProject + demo states must keep their existing guards (write controls stay
  hidden/disabled per R7RO.1); this ticket only changes presentation.
- Follow `dom-contract.ts` for any new `data-*` names.

## Acceptance (deterministic)

- DOM tests: lock glyph absent on an ordinary draft row, present on a read-only/demo row;
  provenance renders collapsed (≤1 line, or behind a title/aria label); icons per file
  kind asserted by data-hook; hover affordance via the `ui-*` interactive class.
- `pnpm turbo build lint typecheck` + web suite + `check:dom-contract`/`spa-budget`/`spa-env` green.
- Preview walk: files panel screenshot on a project with mixed draft/delivered/demo rows.

## Out of scope

- Tree behavior changes (expand/reorder), new file kinds, editor integration.
