## Goal
Replace the nonfunctional edge-signed CDN delivery (LB→bucket origin read denied) with GCS V4
signed URLs that the api mints after a tenant check. The §13.3 usercontent isolation properties
must keep holding: non-allowlisted types are served as attachments, no cookies, no path to session
scope.

## In scope — deliverables
1. A mint helper — **owned shared decision, consumed by R6POST.1 and R6SECR.1**: tenant check
   before minting; short TTL; `response-content-disposition=attachment` +
   `application/octet-stream` for non-allowlisted types; no cookie ever.
2. Every usercontent read path routed through it; the CDN signed-key path is left inert (not
   relied on).
3. `usercontent-cdn-verify.mjs` re-pointed at the minted path: unsigned → denied, signed → 200,
   tampered or expired → denied, header leg.
4. **ADR-113** amending the §13.3 usercontent-origin contract, plus a dated amendment banner in
   `docs/rhema-design-spec.md` §13.3.
5. The two-tenant probe extended to the mint route (invariant 13).
