# 313_R6FIX.42 — preview-orphan sweep gcs-bucket arm: `storage.buckets.list` custom role

**Status:** done (Stage A structural pin; cloud apply rides the prod stack's next `pulumi up`)
**Class:** run-time insert — infra grant defect (least-privilege assumption falsified live)
**Base:** `origin/main` @ `2eb195ab`

## Defect

The nightly `preview-sweep` workflow has failed every night since it gained the `gcs-bucket`
scan arm (first red 2026-11-18; still red 2026-11-23): `gcloud storage buckets list` →
**HTTPError 403 `storage.buckets.list` denied** for the `github-pool` repo principalSet.

Root cause is a wrong least-privilege assumption authored 2026-11-17 (`sweepViewerRoles` in
`infra/pulumi/journeys.ts`): the comment claimed `roles/storage.objectViewer` is "the least
role carrying" `storage.buckets.list`. It is not — `gcloud iam roles describe` shows
objectViewer grants object *reads* (`storage.objects.get/list`), never the project-level
`storage.buckets.list`. The only predefined role carrying it is `roles/storage.admin`
(object/bucket delete + IAM mutation — far too broad for a read-only orphan sweep).

Every other arm passes (the principalSet binding itself works — only this permission is
missing), so the sweep has been running blind to the one resource class the pr-385 leak that
motivated it included: preview GCS buckets.

## Implementation

`infra/pulumi/journeys.ts`:

- `roles/storage.objectViewer` leaves `sweepViewerRoles` — it never did the job and grants
  object-content reads the sweep doesn't need.
- New `gcp.projects.IAMCustomRole` `ciPreviewSweepBucketsList` with exactly
  `permissions: ["storage.buckets.list"]`, bound to the same
  `attribute.repository/${args.ciRepository}` principalSet via `gcp.projects.IAMMember`
  `ci-preview-sweep-buckets-list` (`retainOnDelete` like its peers).

`infra/pulumi/journeys.test.ts`: the wrong pin flips to pin the fix — requires the
`IAMCustomRole`, `roleId`, and the single permission; denies `roles/storage.objectViewer`
and `roles/storage.admin` anywhere in the source.

## Apply-time note (for the deploy leg)

Removing `ci-preview-sweep-storage-objectViewer` from the program deletes the IAMMember
resource but `retainOnDelete` keeps the GCP binding alive. Post-`up`, revoke it once:

```bash
gcloud projects remove-iam-policy-binding rhema-507501 \
  --member 'principalSet://iam.googleapis.com/projects/25012989319/locations/global/workloadIdentityPools/github-pool/attribute.repository/SteveVitali/Rhema' \
  --role roles/storage.objectViewer
```

That revocation only tightens the sweep identity (nothing else uses it; the sweep's own arms
keep their per-class viewers).
