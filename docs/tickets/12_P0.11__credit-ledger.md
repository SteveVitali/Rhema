## Goal
The money layer under every run: ledger operations (`grant/hold/debit/release/expire/refund/adjustment`),
the balances table's transactional maintenance, the cap-clamped debit math, and the REQ-SPEC-24
integrity rules that Phase-0 runs and the beta's billing both stand on.

## In scope — deliverables
1. **Ledger ops** with idempotency keys; bucket vocabulary (`included/topup/trial_pocket/daily/promo`);
   consumption order trial/daily → promo → rolled-over → included → top-up (REQ-BILL-15); holds pin
   a bucket and extend its expiry by the held amount (REQ-SPEC-24.3).
2. **Balances:** `credit_balances` maintained in the ledger's own transaction with
   `check (available >= 0)`; nightly `balances = Σ ledger` assertion job (REQ-SPEC-24.1).
3. **Holds:** placed under a row lock on the billing account (two concurrent sheets cannot both fit
   one balance — REQ-SPEC-24.2); released ≤60 s after terminal state (REQ-RUN-13).
4. **Cap-clamped debits:** per-phase debit = `min(actual, cap − Σ debits)` under the run row's lock;
   remainder booked `adjustment(absorbed)`; the DB constraint trigger is an assertion that must
   never fire (REQ-BILL-3 amended); overrun-at-cap booking to the variance reserve (REQ-RUN-12).
5. **Refund semantics:** failed/refused/system-cancelled runs refund their debits; user stop debits
   completed phases only; a refunded partial later resumed re-debits refunded phases first
   (REQ-SPEC-24.6); resume re-validates entitlements and re-prices remaining phases, opening a
   spend gate for deltas (with P0.10; REQ-SPEC-24.3).
6. **Circuit breaker:** Σ absorbed adjustments in 24 h > X% of gross usage → cap multiplier for new
   runs 2× + page (REQ-SPEC-24.5); 30-day parked-run auto-cancel with release (REQ-SPEC-24.4, with
   P0.08's `parkedUntil`).
7. **Rate tables:** versioned `rate_table_version` application when rating proxy rows into debits
   (REQ-BILL-2); `/pricing/rates` publication endpoint stub (full page PRB.8/P1.16).
