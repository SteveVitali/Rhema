## Goal
Make the server answer `/demo`, `/demo/<essay>/…` and `/p/demo~<essay>/…` from static snapshots,
logged out and logged in, on every device class. No session, no tenant, and no API or DB read on
any demo path (ADR-126). Every write is refused before it reaches a DataSource. When this lands,
the shell, the twins, the asset route and the `/demo` SSR frame exist for 220a (SPA boot and URL)
and 221/221a (side effects, hub) to build on.

## In scope — deliverables
1. **The registry.**
   - In `@rhema/contracts`: `DEMO_SLUG_PREFIX`, `isDemoSlug` (registered essays only), the essay
     registry and `DEMO_ROUTE_IDS` (the allowlist shared by server and SPA).
   - Add `/demo` to `SPA_PUBLIC_ROUTES`. `SPA_SURFACES` is unchanged.
   - A property test that `isDemoSlug` and `spaRouteFor` agree, and that api `slugify` never emits
     `~`.
   - *(REQ-DWEB-1)*
2. **The demo guard**, registered before the `/session` and `/p` handlers (R3 §3 S1).
   - Non-GET/HEAD gets 405 `{error:"demo_read_only"}` (JSON, or a terminal SSR notice).
   - A non-allowlisted GET, or an unknown `demo~` slug, gets a terminal 404 document, never the
     shell.
   - Zero DataSource calls of either kind.
   - Header literals carry the `never-cookies exempt` annotation, or the guard module sits outside
     the `check:no-cookies` TARGETS (RV-35).
   - *(REQ-DWEB-2, REQ-DWEB-4)*
3. **`demoDataSource`.**
   - Typed `Pick<DataSource,…>` over exactly the methods R3 §1 enumerates. That list is
     **provisional**: per the DWEB-3 amendment, 221's regenerated table finalizes the set.
   - Every other key is a throwing `DemoUnsupported` proxy.
   - It reads 218/218a's snapshots from disk, lazily per artifact. It has no `fetch`, no
     `process.env`, and no runtime import of `@rhema/api-client`, `@rhema/db` or
     `@rhema/live-clients`; an ESLint boundary rule plus a module-graph scan enforce that.
   - `postAnalyticsEvent`/`postAcquisitionEvent` are no-ops.
   - Snapshot JSON is never `import`ed into a bundle.
   - *(REQ-DWEB-3)*
4. **The nested JSON app.**
   - `createWebApp({dataSource: demoDataSource, session: () => DEMO_SESSION, collabWsUrl: undefined, demo: true})`.
     It answers demo **twins only**, through a forwarded request with `cookie`/`authorization`
     stripped. `set-cookie` is deleted on the way back.
   - Twins carry the ReadOnlyProject `demo` reason (211), `readOnly:true`, no `collabWsUrl`,
     `showcase:false` and no `activeRun`.
   - `ideContext` drops the out-of-demo palette rows (R3 §2).
   - A public `GET /bff/demo/feed-labels` (the server half of 220a's boot fix).
   - *(REQ-DWEB-4, REQ-DWEB-5; S-2)*
5. **The demo shell and boot payload** (server half of REQ-DWEB-6).
   - `spaShellDocument` is served by the **outer** app, so there is a single CSP nonce, at both
     `/demo/<essay>/…` and `/p/demo~<essay>/…` (220a's S-1 outcome decides which the SPA treats as
     canonical, or adds the 302).
   - Boot carries `demo:{essay, slug, signedIn}` and the build SHA, with **no** `principal`,
     `theme:{}`, and every in-scope routeId `"spa"` on every device class (no `SsrHandoff` on a
     phone UA).
   - `projectSlugFor` maps `/demo/<essay>` correctly.
   - `signedIn` is cookie *presence* only, and is cosmetic.
   - *(REQ-DWEB-6 server half, REQ-DWEB-8; S-5; ADR-126's REQ-ED-12 amendment)*
6. **The `/demo` public SSR frame.**
   - The route, a `doc-meta` title/description/OG, and the N10 head contract.
   - An empty hub frame carrying `data-demo-root` for 221a to fill.
   - `/demo/<essay>/…` titles are set.
   - *(contributes to REQ-DWEB-9; primary 220a)*
7. **SHA-keyed twins** (S-13).
   - Demo twin URLs carry `?b=<sha>` from boot.
   - Twins send explicit `cache-control: public` with long TTLs and an ETag of snapshot hash plus
     deploy SHA, which overrides the authed `no-store` floor.
   - The demo shell sends `no-cache`.
   - A header test covers both. *(REQ-DWEB-10)*
8. **The asset route** `GET /bff/demo/asset/:essay/:file`.
   - It serves only files allowlisted in `PROVENANCE.md`, from the image, with an immutable cache
     and an allowlisted `content-type`. Anything else gets a 404.
   - Images in demo Pages resolve to it (`img-src 'self'`).
   - Tested on the synthetic fixture's image. The Figures-list card render over it is 220a's.
   - *(REQ-DWEB-17; S-7)*
9. **The corpus in the image.**
   - `@rhema/web` declares `@rhema/demo-corpus` as a **production** dependency.
   - No `files` field drops `corpus/`.
   - A runtime-stage image-content assertion (`RUN test -s …` on a corpus and a snapshot file)
     fails the build if the data is missing.
   - Snapshot JSON appears in no `public/spa` chunk (`check:spa-budget` green, no ceiling
     raised). *(REQ-DOPS-2)*
10. **The DOM contract.**
    - Create the `demo` bucket in `DomContractSurface` (manifest type only; not `SPA_SURFACES`).
    - Add the hooks this ticket emits (`data-demo-root`, and any others).
    - Each hook is declared, emitted and asserted. 220a, 221, 221a and 222 extend the bucket.
    - *(feeds REQ-DWEB-12, owned by 221)*
11. **The R3 §7 security tests 1–8.**
    - Each runs against the outer app with a throwing, recording `dataSource`.
    - Covered paths: `GET` on `/demo`, `/demo/:essay`, and every allowlisted
      `/p/demo~x/…` and `/bff/p/demo~x/…` path.
    - Each is checked both with no cookie and with a session cookie: 200, **zero** outer calls,
      byte-identical JSON, and no `Set-Cookie` (including `rhema_fp`).
    - Also covered: writes get 405; non-allowlisted GETs get a terminal 404; and a
      single-`nonce`-per-`<script>` assertion holds.
    - *(REQ-DWEB-2, REQ-DWEB-3, REQ-DWEB-4, REQ-DWEB-5, REQ-DWEB-8)*
12. **The staging DEFERRALS row** (`GD-PREVIEW.R7`). Open `D-R7DEM.4-1`: why deferred =
