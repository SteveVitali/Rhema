## In scope — Stage A (code + tests, PR-able)

1. **Margin in the pane system (REQ-IDE-23 amended).** Findings render as decorations on the
   frozen reviewed version — and as **projections** onto a later human-revised version with a
   "from Review of vN" label on each card; a lost anchor moves the card to *Whole piece* with
   "passage changed — still applies?" — unanchored findings head the list and are never
   dropped. Styling per §5.7: underline **weight** encodes severity (blocking solid 2 px ·
   major solid 1.5 px · minor dotted · note faint), **hue** encodes kind (claim amber ·
   discourse violet · argument blue · craft teal · voice/continuity rose), overlapping anchors
   stack with a numbered tick, all marks ≥3:1 against the paper (the P1.01 contrast suite should
   cover these hues). The View menu's *Finding cards* toggle collapses to ticks-only; *Show
   suggestions inline* renders a suggestion-bearing finding's replacement as a read-only
   preview beside the passage.
2. **Three surfaces, one list (REQ-IDE-24).** Margin cards, the Desk Findings list, and the
   Approve-triage card consume the same `Finding[]` with linked selection and shared filters:
   severity, kind, origin, disposition, section, has-URL, has-suggestion, open obligations.
   The Desk list is the screen-reader surface (P1.01's landmark contract): Margin decorations
   are `aria-hidden` with `aria-describedby` on the underlines; the list is a real table/list
   landmark.
3. **Triage mode (REQ-SPEC-7).** `⌘⇧T` — and the primary button on a fresh dossier above 30
   findings: the Desk list becomes a queue grouped by section, sorted blocking → major → minor
   → note within each section, with the progress pill ("23 / 150 decided" — plus the
   open-obligation count), *Next undecided*, and one finding at a time in the Margin with its
   passage scrolled into view. The five verbs, Apply and `J`/`K` work as everywhere; leaving
   triage mode keeps every decision.
4. **Margin clustering.** Above ~30 findings, or whenever >1 finding anchors inside one
   paragraph, the Margin renders one stacked chip per paragraph ("4 findings · 1 major") that
   expands on focus — automatic, no setting.
5. **Apply — the free verb (REQ-SPEC-6).** A finding with `suggestion.replacement` offers
   **Apply** as its primary button — for `note` severity the *only* primary (Accept moves to
   the overflow). Apply writes the replacement into the working head **now, for free**, as a
   plain transaction with provenance `suggestion_applied` — forking to `v(N+1)
   origin=human_revision` if the version is frozen (typing already forks) — and records the
   disposition `accept · status: done · by: user · applied: true · moveId: human`. Disabled
   while a writer-run holds the lock, with the queue explanation. The next Revise run treats
   applied moves as made moves ("Revise using your edits", §6.3 — the data path is the
   disposition row; assert the run input can see them).
6. **Dispositions → ledger.** Each verb writes a `status: proposed, by: user` row and collapses
   the card; **rationale required for rebut and escalate only** (the REQ-MOBILE-11-amended rule,
   shared verbatim); *defer* pre-fills "Not this round" (editable); *adapt* opens an editable
   box pre-filled with the suggestion; accept/adapt/apply never require text. Pre-triage
   dispositions pass to the Revise sheet as highest-precedence guidance ("you pre-triaged 14 of
   41" — wire the count into P1.06's sheet surface). At delivery the ledger freezes: cards lock
   and each row links forward to its move + changed range in v(N+1) (the link target is
   P1.08's compare — land the frozen state + the link seam now).
7. **Bulk with one preview (REQ-IDE-29 amended).** *Apply all notes*, *Defer all minor*,
   *Accept all in §III* open **one** consolidated preview — a checklist with unchecks plus a
   single diff for applied suggestions — computed on a scratch copy; **no blind accept-all
   exists**.
8. **Drafter-proposes-first.** Above 30 findings, the next-step card advertises "Let the Drafter
   propose a triage, then decide the N it can't"; the Approve-triage card (which waits) opens
   with **Approve proposals** primary, escalations pinned first, and per-row overrides that
   write ledger rows with `actor: user` provenance (PRB.05's triage routes carry the write
   path — reuse).
9. **Evidence + reconciliation.** Claim findings show the verdict chip and every
   `sources[]` edge with stance (supports / contradicts / contextualizes) and accessed date —
   each URL carries the **"fetched ✓"** chip derived from the run's fetch log (REQ-IDE-25); the
   once-per-surface explainer line ("Every link here was actually opened and read by the
   Editor during this run — never quoted from memory") shows on the first dossier. Second-read
   reconciliation renders: corroborated (✓✓), second-read-only kept, and rejected — collapsed
   with the Editor's reason, no disposition controls, but **promotable** ("I want to address
   this anyway" → user-origin ledger row). A finding the user pre-triaged that reconciliation
   later rejects surfaces as a **conflict row** ("you accepted this; the Editor withdrew it —
   keep your disposition?") — never silently dropped (REQ-IDE-15's amended half completes
   here; note it).
10. **Obligations on the surface.** Blocking/major cards carry the obligation-state chip
    (`open · addressed · discharged · rebutted · deferred · mooted` — `mooted` renders as
    discharged-pending until confirmed at the next triage); triage mode's progress line adds
    "obligations: N open"; "Add to obligations" is offered on any finding; free-form
    obligations come from the palette (`source: 'user'`) once P1.06's palette exists — wire the
    row-creation path here.
11. **Rubric + letter integration.** The rubric view (Desk › Findings › Rubric — eight
    five-dot scales, caps with reasons + linked findings, never an aggregate; REQ-IDE-30 was
    PRB.04's — integrate into the Desk tab) and the letter-on-Page behaviour: passage links in
    the letter resolve to finding links, and while the letter is on the Page the Margin shows
    the referenced finding cards (each opens the passage in a split below the letter).
12. **Keyboard chords (§5.12 rows).** `J`/`K` next/previous, `P` apply, `A D R F E` the five
    verbs, `Enter`/`Esc` open/collapse, `⌥J`/`⌥K` next major-or-blocking — **active only while
    the Margin or Findings list has focus; inert while the caret is in the Page** (P1.06's
    dispatcher enforces the scope; this ticket binds the behaviours).
13. **Severity budget.** The Quick notch's 40-finding cap renders honestly — the list shows
    the capped set and the letter's roadmap carries the folded-in counts ("…plus 23 copy-edit
    notes folded into the roadmap"); assert the count line against the sidecar numbers.
14. `turbo build lint typecheck` + `pnpm test` green; vocabulary lint on disposition/severity
    strings (blocking · major · minor · note; accept · adapt · rebut · defer · escalate —
    verbatim, no synonyms).
