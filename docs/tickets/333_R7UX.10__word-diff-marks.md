## Goal

BL-88 (R5 G1): the compare view shows only paragraph-level tinting. Add word-level marks:
inside a changed paragraph, the inserted/deleted *words* get the stronger mark while the
paragraph keeps its tint. Keep the diff algorithm simple and honest — a word-boundary
LCS or the repo's existing diff helper if there is one (check `packages/` for a vendored
diff before writing one); performance bound: a 100 KB document pair must diff under the
budget the compare view already spends (record the measured number).

  via `dom-contract.ts` names) + `packages/editor` if the diff lives there.
- The paragraph-tint rendering is the existing path — word marks nest inside it; deleted
  words strike-through, inserted words underline/solid mark per the design system's
  existing compare palette.

  changeset format, name it in the run ledger so the 1.x work reuses it.

## Acceptance (deterministic)

- Unit: word-diff on fixture pairs produces correct insert/delete spans (incl. unicode
  words, punctuation, the no-change fast path); a paragraph with zero word changes gets no
  word marks.
- DOM: the compare view renders word-level mark elements inside a changed paragraph;
  unchanged paragraphs unchanged.
