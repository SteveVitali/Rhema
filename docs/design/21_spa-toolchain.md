### F1 — `vite.config.ts` belongs in `apps/web/`, not the repo root

**Claim:** The correct placement is `apps/web/vite.config.ts` scoped to the `@rhema/web` package.
Every build graph primitive in this repo is per-package: `apps/web/package.json:17` runs its own
`tsc -b && node build-client.mjs`; `turbo.json:8-24` defines package-scoped tasks with
`outputs: ["dist/**"]` relative to the package dir; the Dockerfile builds via
`pnpm --filter @rhema/web... build` (`apps/web/Dockerfile:15`); and ADR-007's rejected-alternative
analysis priced the toolchain cost *inside `@rhema/web`* — the package boundary is where the cost
lands and where it should be configured. A root config would drag `apps/api`, `apps/collab`, and
every `packages/*` into a tool only the web client needs, and would make the `vite build` step a
root-turbo orphan (root `package.json:12-24` runs `turbo run build` — package tasks).
**Status:** VERIFIED (repo mechanics; placement itself is a recommendation)
**Evidence:** `apps/web/package.json:16-22`; `turbo.json:8-13`; `apps/web/Dockerfile:9-16`;
`package.json:12-24`; `docs/adr/ADR-007-beta-shell-react-ssr-no-vite.md:17-22`; B1 §6
(`docs/design/20_spa-framework-binding.md:350-353` — "Vite owns only `src/spa/**`").
**Retrieved:** 2026-10-07T22:15:00Z
**Implication for the spec:** `apps/web/vite.config.ts`; `build` script becomes
`tsc -b && node build-client.mjs && vite build` (or `build:spa` sub-step); `vite`/`@vitejs/plugin-react`/
`@tanstack/router-plugin` are `@rhema/web` devDependencies only — nothing at the root.
**Outline delta:** CONFIRMS B1 §6; EXTENDS with the concrete script wiring.

### F2 — The `publicDir` collision resolves by disabling Vite's `publicDir` and nesting `outDir` inside the existing generated dir

**Claim:** `apps/web/public/` is a **generated output directory**, not a static-source dir: it is
populated only by `build-client.mjs` (islands → `public/<entry>.js`, fonts → `public/fonts/`),
gitignored (`.gitignore:38`), ESLint-ignored (`eslint.config.js:34`), and consumed by `readFile`
routes resolving `../public/…` from both `src/` and `dist/` (`server.ts:5645-5667`). Vite's default
`publicDir` (`<root>/public`, copied verbatim into `outDir`) pointing at that dir would (a) copy the
esbuild islands and fonts *into* the SPA output, (b) recursively copy the SPA output into itself if
`outDir` nests under it, and (c) be wiped by `vite build`'s `emptyOutDir` on each rebuild — three
distinct breakage modes. The fix: **`publicDir: false`** (this project has no Vite-managed static
assets — fonts already have a pipeline) and **`build.outDir: "public/spa"`** so the SPA output lands
inside the one artifact dir the server and image already carry.
**Status:** VERIFIED
**Evidence:** `apps/web/build-client.mjs:15-48` (the only writer of `public/`); `.gitignore:36-38`
("generated by apps/web/build-client.mjs … never committed"); `eslint.config.js:33-34`;
`apps/web/src/server.ts:5645-5667` (`new URL("../public/…", import.meta.url)` reads);
`apps/web/Dockerfile:28-30` ("`pnpm deploy` only carries package files, so copy the built assets
explicitly" — `/repo/apps/web/public` → `/app/public`); D2 F9's collision flag
(`docs/design/28_spa-safety-gates.md:94`). Vite publicDir/outDir semantics: https://vite.dev/config/build-options + https://vite.dev/config/shared-options#publicdir.
**Retrieved:** 2026-10-07T22:15:00Z
**Implication for the spec:** Layout decision is: keep `public/` as THE served-asset root;
`outDir: "public/spa"`; `publicDir: false`. Consequences — `Dockerfile:30` COPY covers SPA output
for free (zero Dockerfile copy change); `.gitignore:38` and `eslint.config.js:34` already exclude it
(REQ-SAFE-10's "move together" lands as TARGET_DIRS only); `emptyOutDir` warnings must be
acknowledged since outDir nests under the package root but NOT under `publicDir` (disabled — no
recursion hazard); `vite build` empties only `public/spa/`, islands/fonts untouched.
**Outline delta:** RESOLVES D2's open question (`28_spa-safety-gates.md:113`) — `public/` neither
retires nor becomes Vite's static dir; it stays the generated-asset root with `spa/` as a new
sub-tree. CORRECTS any plan that assumed `dist/` — Vite's default `outDir` is overridden.

### F3 — There is no dev server today; the honest baseline is `vite build --watch` + a watched Node server, with `vite dev`+HMR as an opt-in that costs a dev-only CSP delta

**Claim:** The repo has **no `dev` script anywhere** — no `package.json` in the workspace declares
one (grep over all `package.json`: only `build/typecheck/lint/test/start`); the web server runs as
`node dist/main.js` after `pnpm build` (`apps/web/package.json:17,21`; `main.ts:248-253`), and the
islands rebuild only via `build-client.mjs`. So "does `vite dev` run alongside Hono" has no incumbent
to compare against — the question is what *new* dev loop to specify. Three layers, honestly priced:
(a) **Vitest** already transpiles client sources without a build (`vitest.config.ts:4-8`) — most
component/logic iteration needs no browser at all; (b) **build-watch baseline**: `vite build
--watch` emits fresh hashed bundles into `public/spa` on save; `tsx watch src/main.ts` (tsx is
already a root devDep, `package.json:35`) or `node --watch dist/main.js` + `tsc -b --watch` covers
server edits; page reloads are manual. Zero CSP divergence — bundles are same-origin `'self'` with
the same nonce path as prod; (c) **full `vite dev` HMR**: requires the shell doc to emit
`<script type="module" src="http://localhost:5173/...">` (a second origin), which the CSP would
block unless a dev-only env (e.g. `SPA_DEV_ORIGIN`) widens `script-src` + `connect-src` (HMR WebSocket)
*only when set*, plus a hand-emitted react-refresh preamble (Vite's `@react-refresh` inline script —
which the nonce middleware can stamp, `server.ts:359` matches any `<script`), plus
`server.cors.origin`/`appType:"custom"` config per Vite's backend-integration guide.
**Status:** VERIFIED (repo facts); the option-c recommendation is design judgment
**Evidence:** grep `"dev"` across workspace `package.json` files — zero matches;
`apps/web/package.json:16-22`; `apps/web/src/main.ts:248-253`; `package.json:35` (tsx);
`vitest.config.ts:5-19`; CSP middleware `server.ts:341-371`; Vite backend-integration guide
https://vite.dev/guide/backend-integration (`server.cors.origin` + manifest flow);
`@vitejs/plugin-react` README (Fast Refresh preamble) https://unpkg.com/@vitejs/plugin-react@6.1.1/README.md.
**Retrieved:** 2026-10-07T22:15:00Z
**Implication for the spec:** Spec the baseline as (b): one `pnpm dev`-style script per
`AGENTS.md`-era conventions is net-new but required for the migration to be workable — recommend
`"dev:spa": "vite build --watch"` + `"dev": "tsx watch src/main.ts"` documented as two panes.
Option (c) MAY be added behind `SPA_DEV_ORIGIN` with an explicit, documented dev-only CSP relaxation
(`script-src`/`connect-src` gain the dev origin only when the env var is set, fail-closed absent) —
but it is NOT the default loop, because it forks the CSP posture the tests pin
(`usercontent-csp.test.ts:104-134`).
**Outline delta:** NEW — no prior dev-loop spec existed; EXTENDS the strangler story (server edits +
client edits both need a rebuild+reload story while SSR is still live).

### F4 — `autoCodeSplitting` concretely requires file-based routing + `@tanstack/router-plugin` registered BEFORE `plugin-react`; the route tree is a generated artifact the typecheck must see

**Claim:** Automatic per-route splitting exists only under file-based routing with the bundler
plugin (B1 F4 verified the doc); concretely in `apps/web/vite.config.ts`:

```ts
plugins: [
  tanstackRouter({
    target: "react",
    autoCodeSplitting: true,
    routesDirectory: "src/spa/routes",
    generatedRouteTree: "src/spa/routeTree.gen.ts",
  }),
  react(), // MUST follow tanstackRouter — plugin order is load-bearing
],
```

The plugin (a) generates `src/spa/routeTree.gen.ts` (the typed route tree `main.tsx` imports), and
(b) wraps each route's `component`/`errorComponent`/`pendingComponent`/`notFoundComponent` in
`React.lazy`-equivalent lazy imports, while `beforeLoad`/`loader`/`validateSearch` stay in the
eager graph — meaning **any module imported by route config ships in the entry chunk**. The
editor/collab heavy tail (ProseMirror + Yjs + `@hocuspocus/provider` + `y-indexeddb` +
`y-prosemirror`, the ~400 kB gzip group D2 sized at `28_spa-safety-gates.md` F6) lands in a lazy
chunk only if it is imported *exclusively* from `.lazy`/component files — a single eager import of
`@rhema/editor` or `pageSessionRegistry` from a route-config file silently pulls it into the entry.
`routeTree.gen.ts` additionally creates a build-ordering obligation: `tsc -p tsconfig.spa.json`
fails if the file doesn't exist, so it is either **committed** (regenerated on every route change;
diffable, reviewable — matches this repo's committed-artifact tolerance for
`packages/protocols`) or **generated pre-typecheck** via `@tanstack/router-cli` (`tsr generate`) —
committed is recommended so the typecheck step stays a pure `tsc -p`.
**Status:** VERIFIED (plugin behavior per docs + B1); the eager/lazy boundary consequence is a
design inference from the documented split semantics
**Evidence:** https://tanstack.com/router/latest/docs/guide/code-splitting ("automatic
code-splitting … ONLY available when you are using file-based routing with one of our supported
bundlers" — already cited B1 F4); TanStack file-based-routing/plugin config docs
https://tanstack.com/router/latest/docs/routing/file-based-routing.md; B1 OQ2
(`20_spa-framework-binding.md:451-455`); B4's module-scope session-registry design
(`23_spa-editor-collab-binding.md` F5) — the registry is exactly the module that must not be
eager-imported; repo typecheck pattern `apps/web/package.json:18` (`tsc -p tsconfig.client.json`).
**Retrieved:** 2026-10-07T22:15:00Z
**Implication for the spec:** This is the concrete input to **B1 open question 2 → file-based
routing is the answer** (`autoCodeSplitting` + generated typed route tree beat manual `.lazy()`
discipline on ~33 routes). The spec must pin: the plugin options block above; plugin ordering; the
"route config imports no heavy modules" rule enforced by the REQ-SAFE-7 budget script (entry ≤250 kB
fails the build the day someone eagerly imports the editor); and the routeTree.gen.ts check-in
decision. Lazy-chunk layout: entry = React+Router+Query+shell+`bff.ts`; per-route lazy chunks; the
`page`/`v`/`a` document routes' components pull the editor/collab graph as the dominant lazy group —
`manualChunks` is a tuning knob, not a first-cut requirement.
**Outline delta:** RESOLVES B1 OQ2 (recommend file-based — spec line needed); EXTENDS F4 with the
eager-import hazard and the codegen/typecheck ordering.

### F5 — Manifest-driven document assembly: `build.manifest: true` → `public/spa/.vite/manifest.json`; the shell route resolves the entry once and serves `/assets/spa/*` from `public/spa/`

**Claim:** With no `index.html` (the shell is a Hono-served string template per C3 F6), the backend-
integration shape is: `build.manifest: true` emits `outDir/.vite/manifest.json` mapping each source
entry to `{file, isEntry, imports[], css[], dynamicImports[]}` with content-hashed filenames.
`renderSpaDocument` (named in B1 §1/C3 §shell) reads the manifest **lazily once, cached in module
scope** (the bundle is image-baked — `RHEMA_BUILD_GIT_SHA` provenance, `Dockerfile:22-23` — so the
manifest cannot change under a running process; no per-request read, no dev-mode variance) and emits:
`<script type="module" src="/assets/spa/<entry.file>">` + `<link rel="modulepreload"
href="/assets/spa/<import.file>">` for each `imports[]` entry + `<link rel="stylesheet">` for each
`css[]`. Serving: one new route `GET /assets/spa/*` → `readFile("../public/spa/<rest>")` with the
same name-gating discipline as `/assets/fonts/:file` (`server.ts:5658-5667`): regex
`/^[\w.-]+\/[\w./-]+$/`-class gate rejecting `..`, dot-segments (blocks `.vite/manifest.json` from
the URL space entirely), and `.map` files; missing artifact → the existing empty-404 convention
(`server.ts:5648`). Cache profile: Vite outputs are all content-hashed → `public, max-age=31536000,
immutable` (the fonts precedent, `server.ts:5665`); islands keep `no-cache` (unhashed names,
`server.ts:5651`). CSP is satisfied by construction: module scripts and modulepreloads are
`'self'`-covered, the nonce middleware stamps the entry tag like every other `<script`, and
`build.modulePreload.polyfill: false` suppresses the one *inline* script Vite would otherwise need.
**Status:** VERIFIED (Vite manifest semantics per official docs; repo serving/cache/CSP per files)
**Evidence:** https://vite.dev/config/build-options (`build.manifest` → `.vite/manifest.json`,
"used by a server framework to render the correct asset links");
https://github.com/vitejs/vite/blob/main/docs/guide/backend-integration.md (manifest shape:
`file`/`isEntry`/`imports`/`css`/`dynamicImports`); `server.ts:5640-5667` (asset route + fonts
immutable profile); `server.ts:354-371` (nonce stamp on any `<script` incl. `type="module"` —
lookahead `[\s>]` covers it); `render.tsx:150` (the island tag the SPA tag mirrors); modulepreload
polyfill-as-inline-script concern per D2 F5 (`28_spa-safety-gates.md:54,56`).
**Retrieved:** 2026-10-07T22:15:00Z
**Implication for the spec:** Pin the layout contract: disk `public/spa/assets/<name>-<hash>.js`,
`public/spa/.vite/manifest.json`; URL `/assets/spa/assets/<name>-<hash>.js` (a straight prefix mount
— the `assets/` segment stays in the URL; simplest, no rewrite layer). Manifest-absent ⇒ shell
document without script tags (the same degrade-never-fail posture as the islands' empty-404,
`server.ts:5641-5644` comment) + a structured log line. NOT build-time inlining: `server.ts` is
tsc-compiled before `vite build` runs, so inlining would need a post-build codegen — runtime
read-once is strictly simpler.
**Outline delta:** EXTENDS C3's shell-doc spec (`26_spa-public-auth-boundary.md:288-308` — the
`<modulepreload links per Vite manifest>` placeholder becomes concrete) and REQ-FW-10.

### F9 — `tsconfig.spa.json` is a sibling of `tsconfig.client.json`, not an extension of it — adds `jsx`, `vite/client` types, and `src/spa`

**Claim:** `tsconfig.client.json` (`apps/web/tsconfig.client.json`) already establishes the browser-
graph pattern — `lib: ES2022+DOM+DOM.Iterable`, `module: ESNext`, `moduleResolution: Bundler`,
`composite:false`, `noEmit` — but its `include` is `["src/client"]` and it lacks JSX config. Two
options: (a) edit it to `["src/client","src/spa"]` + `"jsx": "react-jsx"` — one browser config,
simplest, but blurs the island/SPA boundary the strangler relies on (island sources suddenly
typecheck under JSX+`vite/client` types they don't use); (b) **sibling `tsconfig.spa.json`**
extending `../../tsconfig.base.json` with the client overrides *plus* `"jsx": "react-jsx"`,
`"types": ["vite/client"]` (gives `import.meta.env`/`import.meta.hot` types — consumed only by the
single `env.ts` module REQ-SAFE-8 mandates), `include: ["src/spa", "src/spa/routeTree.gen.ts"]`.
Option (b) is recommended: the two client graphs have different lifetimes (islands shrink to one
file; the SPA grows to ~33 routes) and keeping them separate makes the island-deletion diff trivial.
`typecheck` becomes `tsc -b && tsc -p tsconfig.client.json && tsc -p tsconfig.spa.json`; the ESLint
DOM-globals block (`eslint.config.js:116-142`) needs `apps/web/src/spa/**` added (browser globals —

## Design (the concrete vite.config.ts)

// apps/web/vite.config.ts — SPA bundle for the auth'd shell (B2/REQ-TL-*). Islands stay on
// build-client.mjs/esbuild; this file owns ONLY src/spa → public/spa.
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { tanstackRouter } from "@tanstack/router-plugin/vite";

export default defineConfig({
  appType: "custom",                 // no index.html — the shell is a Hono-served template (C3 F6)
  publicDir: false,                  // apps/web/public is a GENERATED dir (F2) — never copy it
  plugins: [
    tanstackRouter({                 // MUST precede react() (F4)
      target: "react",
      autoCodeSplitting: true,
      routesDirectory: "src/spa/routes",
      generatedRouteTree: "src/spa/routeTree.gen.ts",
    }),
    react(),
  ],
  build: {
    target: "es2022",                // matches the islands' esbuild target (build-client.mjs:24)
    outDir: "public/spa",            // inside the existing served-asset root → Dockerfile:30 free
    assetsDir: "assets",             // default; URLs become /assets/spa/assets/<name>-<hash>.js
    manifest: true,                  // → public/spa/.vite/manifest.json (F5)
    sourcemap: "hidden",             // maps for REQ-SAFE-2 provenance scan; never linked/served (F6)
    modulePreload: { polyfill: false }, // the inline polyfill script would need a nonce slot (F5)
    rollupOptions: { input: "src/spa/main.tsx" },
  },
});

Companion shape — the serving route (F5), mirroring the fonts gate:

```ts
// server.ts, next to the CLIENT_ENTRIES loop:
app.get("/assets/spa/*", async (c) => {
  const rel = c.req.path.slice("/assets/spa/".length);
  // Name-gated like /assets/fonts/:file — flat-ish paths only; no dot-segments (blocks ../ and
  // .vite/), no .map (sourcemaps are build-time artifacts, never served — REQ-TL-6).
  if (!/^[\w][\w./-]*\.(js|css|woff2|svg|png|webmanifest)$/.test(rel) || rel.includes(".."))
    return c.body(null, 404);
  const body = await readFile(new URL(`../public/spa/${rel}`, import.meta.url)).catch(() => null);
  if (!body) return c.body(null, 404);
  const type = rel.endsWith(".css") ? "text/css; charset=utf-8" : "text/javascript; charset=utf-8";
  return c.body(body, 200, {
    "content-type": type,
    // every Vite output name is content-hashed → immutable (the fonts precedent, :5665)
    "cache-control": "public, max-age=31536000, immutable",
  });
});
```

And `renderSpaDocument`'s manifest consumption (F5): module-scope `let spaEntry` cache; on first SPA
render `readFile("../public/spa/.vite/manifest.json")`, pick the `isEntry` record for
`src/spa/main.tsx`, emit its `file` as the `<script type="module">`, its `imports[]` as
`<link rel="modulepreload">`, its `css[]` as stylesheet links — all through the existing
nonce-stamping `text/html` middleware (REQ-SAFE-5). Missing/corrupt manifest ⇒ shell without
script tags + one structured log line (the islands' degrade-never-fail convention).

## Open questions

1. **HMR dev-server posture** — `vite dev` on a second origin + `SPA_DEV_ORIGIN`-gated CSP widening
   is specified as opt-in (F3), but is it worth building at all in the first phase? Recommend
   deferring until a developer actually needs it; vitest + `vite build --watch` covers most
   iteration. If deferred, REQ-TL-8 shrinks to the watch-build baseline.
2. **`routeTree.gen.ts` committed vs generated** — this note recommends committing (typecheck stays
   pure `tsc -p`; the diff is reviewable; precedent for committed generated artifacts exists in
   `packages/protocols`). If the parent prefers gitignored, `tsr generate` (`@tanstack/router-cli`)
   must run before `tsc -p tsconfig.spa.json` in both `typecheck` and CI — an extra ordering edge.
3. **`.map` files inside the image** — strip in the Dockerfile builder (recommended) vs ship
   unserved; ties to D2's open question on whether the protocol-marker scan ever runs in-image. If
   an in-image scan is ever wanted, keep the maps.
4. **First-install pnpm check** — whether any Vite 8/Rolldown transitive dep requests a build
   script beyond `esbuild` (F8); resolve on the first `pnpm install` and extend
   `onlyBuiltDependencies` deliberately if needed.
5. **`manualChunks` tuning** — whether autoCodeSplitting's per-route chunks keep the editor/collab
   group under REQ-SAFE-7's ≤400 kB ceiling without manual chunk hints is only answerable on the
   first real manifest; the budget script is the enforcement, `manualChunks` the tuning knob.
6. **SPA dev assets in `pr-<n>` preview stages** — previews build the image, so `vite build` runs in
   Docker and this is handled; but if anyone ever runs the dev loop against a preview api, the
   `SPA_DEV_ORIGIN` story needs a preview-origin variant. Low priority; flag for D3.
