### F4 — Every SSR-mechanics leg has a named SPA-equivalent probe; the generic fix is a mounted-marker + settle contract

### F5 — The phone/rhythm legs: §10.1 must be re-specified as a not-mount capability gate, not CSS hiding; the DOM-absence probes then keep working

**Claim:** P1's §10.1 asserts (`steps.ts:1636-1651,1719-1721`) do `document.querySelector` on banned selectors and fail on any *hit* — `display:none` still hits. So an SPA that "gates client-side" by hiding (CSS/conditional-class) fails the contract even if nothing is usable; only **conditional render** (the components are never in the DOM) preserves the probe semantics. The gate input can't be pure viewport width — a 390-px desktop window is not a phone in the shipped model (P1 distinguishes `sec-ch-ua-mobile` from width; `steps.ts:1496` sets `MOBILE = {"sec-ch-ua-mobile": "?1"}` as headers, not viewport alone). Recommended re-spec: the web server stamps the shell document (and the bootstrap JSON) with `data-device="phone|desktop"` derived from the same `isPhoneUa` signal the SSR uses today — the shell document request *does* see the UA, so no capability information is lost — and the SPA's capability resolver treats that attribute plus `matchMedia("(pointer: coarse)")` as the gate input; components in the §10.1 set render-or-don't-mount on it. Journeys add one probe (`[data-device="phone"]` on `<html>`/`body` when MOBILE headers are set) and keep every existing absence assert unchanged. The reader-Page legs (`data-readonly="1"`, empty `data-collab-url`, `[data-page-banner="readonly"]`, no `[data-version-rail]`, no mounted editable) are already attr-shaped and survive verbatim under a conditional-render contract. "Rhythm" legs — the reload/poll cadences (R6's 25 s reload sampling, meta-refresh cadences, the 10 s lock poll) — become explicit settle waits plus, where the underlying mechanic was a poll, a documented SPA equivalent (SSE/SWR); the cadence numbers are contract and must survive or be consciously re-justified.
**Status:** VERIFIED
**Evidence:** `steps.ts:1496` (`MOBILE` header object), `:1611` (`context.setExtraHTTPHeaders(MOBILE)`), `:1636-1651` (querySelector-absence over `form[action$="/run"]`, `a[href$="/import"]`, `[data-rename-form]`, `form[action="/app/new"]`), `:1662-1709` (reader-Page marker block), `:1714-1721` (`[data-phone-blocked]` + `form[data-run-sheet]` absence on the run sheet); `server.ts:5679` `isPhoneUa` (per A4 F4); `02_island-contract-map.md:105` (phone ⇒ readOnly + no collab wire emitted server-side today); A4 open-question 3 flags exactly this ambiguity ("rendered-but-hidden ≠ never renders").
**Retrieved:** 2026-10-07
**Implication for the spec:** §10.1 must be written as a *mount* contract ("the desktop-capability set is not in the DOM on a phone capability context"), with the capability arriving via `data-device` on the served shell — preserving the server-authoritative signal and the journey probes alike. A viewport-only gate silently changes the contract for narrow desktop windows; call that out as a spec trap.
**Outline delta:** RESOLVES A4's open question 3 in favor of "server stamp + client not-mount"; EXTENDS C1's phone-posture row with the enforcement mechanics.

### F7 — The flip gate: per-surface acceptance = gated step subset green on the flagged build AND on the SSR fallback, with a `data-renderer` marker making "which renderer served" assertable
