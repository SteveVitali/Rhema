# Getting help

## Source code and development

Start with the [development guide](docs/development.md), [testing guide](docs/testing.md), and
[configuration reference](docs/configuration.md). The [architecture guide](docs/architecture.md)
explains where to look for a change.

For a reproducible bug or a development question, search the
[repository's issues](https://github.com/SteveVitali/Rhema/issues), then open one if the problem is not
already covered. Include:

- The commit or branch you are using, operating system, Node.js version, and pnpm version.
- The command or steps you ran and what you expected to happen.
- The actual result and a minimal reproduction using synthetic content.

Remove credentials, session cookies, private writing, and identifying production data from logs or
screenshots. If a failure requires a private setup, describe the missing prerequisite rather than
publishing access details.

## Hosted service

For account, billing, or private manuscript questions about [rhema.tools](https://rhema.tools), use
[contact@rhema.tools](mailto:contact@rhema.tools). Repository issues are public-facing development
discussions and are not an appropriate place for account details.

## Security

Report suspected vulnerabilities privately using [SECURITY.md](SECURITY.md). Do not include exploit
details in a public issue or test the hosted service outside an authorized assessment.
